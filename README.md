# 诗境 · 山河

> 中国古典诗词三维地图教学系统 —— 基于 Three.js 的 3D 交互式古诗教学工具

把 79 处诗境、245 首名篇、1647 句诗文放在一张可以旋转、缩放、点选的立体中国地图上。
每处光柱都是一首诗，每条江河都是一堂课。

**教材覆盖**：统编版小学 108 首 + 初中 84 首 + 高中新课标诗词曲 41 首，共 233 篇，**覆盖率 100%**。

---

## 快速开始

ES Module 无法在 `file://` 协议下加载，请用附带的本地服务器启动：

```bash
cd poetry-3d-map
python3 serve.py            # 默认 http://127.0.0.1:8777，会自动打开浏览器
python3 serve.py 8080       # 指定端口
```

打开后即可使用，**无需联网**（Three.js 与地图数据已全部本地化）。

## 启动失败怎么办

加载页**不会无提示地一直转下去**。页面在模块加载前就装了兜底脚本（`index.html` 顶部）：

- 捕获全局运行时错误与模块加载失败，把原因直接显示在加载页上；
- **18 秒看门狗**：超时未启动会报出「最后停在哪一步」（构建三维地形 / 加载诗词数据 / 生成地势起伏 / 点亮诗境地标 / 装配界面与题库）；
- 进入页面前先做 **WebGL 预检**，显卡或浏览器禁用 WebGL 时给出明确提示；
- 无论哪种失败，都提供「重新加载」与「先进入页面」两个出口。

进度条是**真进度**（由主程序分阶段上报），不是无限滑动的假动画——假动画看不出「在动」还是「卡死」。

常见原因对照：

| 加载页显示 | 原因 | 处理 |
| --- | --- | --- |
| `Failed to fetch dynamically imported module` | 直接双击 `index.html`（`file://`），或没走本地服务器 | 用 `python3 serve.py` 启动 |
| `无法创建 WebGL 上下文` | 浏览器禁用了硬件加速 / 显卡驱动异常 | 开启硬件加速，或改用 Chrome / Edge |
| 停在某一阶段超过 18 秒 | 网络或磁盘较慢，模块（约 2 MB）没加载完 | 检查网络后点「重新加载」 |
| `当前浏览器过旧` | 不支持 ES Module | 换新版浏览器 |

> 本应用使用 `<script type="importmap">` 解析 `three` 这一裸模块名（Three.js 官方推荐做法，
> `vendor/jsm/**` 内部也是以 `from 'three'` 互相引用的）。**请不要绕过 import map 去改 vendor 里的
> 引用路径** —— 那是 Three.js 的标准分发形态，改成相对路径会让日后升级 Three.js 变成手工活。

## 功能一览

### 一、三维诗境地图
- **中国标准 Albers 等积割圆锥投影**（中央经线 105°E，双标准纬线 25°N / 47°N），与国家标准地图一致。
- 版图要素完整：**台湾省、香港特别行政区、澳门特别行政区、南海诸岛（九段线）**全部按标准绘制，默认「全域」视角即可看到完整领土。
- 34 个省级行政区按**平均海拔挤出成 3D 地形**（青藏高原最高、东部平原最低），配色为「青绿山水 → 高原土黄 → 雪线」的高程设色。
- **长江、黄河、京杭大运河**以发光曲线示意，串起沿岸诗境。
- 悬停省份高亮并显示地势类型，右上角实时显示经纬度。
- **2D 平面地图一键切换**（底栏「2D 平面」）：切到正上方俯视、压平地形、收起光柱与云海星空，并锁定旋转，得到一张干净的平面地图；再点一次回到 3D。

### 二、诗词教学主体
- **79 处诗境**：黄鹤楼、白帝城、赤壁、滕王阁、岳阳楼、庐山、西湖、泰山、玉门关、阳关、轮台、蓝关、儋州……
- **245 首诗篇**（先秦至清），每首包含：正文（竖排 / 横排一键切换）、逐联对照译文、词语注释、赏析、意象字、学段标注（小学 / 初中 / 高中必背）。
- **教材全覆盖**：统编版小学 108 首、初中 84 首、高中新课标诗词曲 41 首，共 **233 篇，覆盖率 100%**（见下文「教材篇目覆盖」）。
- **课内诵读专题**：教材中确实系不到具体地点的篇目（咏物、节令、哲理之作，或《诗经》《古诗十九首》这类难以落到一城一地的早期作品）集中收纳为一个非地理专题，不硬编出处。
- 支持**朗读**（浏览器语音合成，选中即诵）。
- 全文检索：按诗名、作者、诗句、地名、背景文字检索并一键飞往。输入后按 `回车` 直接跳往第一条结果。

### 三、点击地图区域 → 当地诗词
教学上最常用的入口：**单击地图上的任一省域**，即可看到「这一带出过哪些诗」。

1. **右侧抽屉**显示该地区介绍：地势类型、收录的诗境与诗篇数、朝代构成、题材分布、境内诗境清单、代表篇目。
2. **底部弹出区域诗词列表**：横向排列该地区的全部诗词卡片（含名句首行），可横向滚动。
3. **点击任一诗词卡片**，弹出**诗词详情弹窗**：正文竖排 / 横排、对照译文、词语注释、赏析、意象字一应俱全，与右侧抽屉里的详情完全同构。

> 地区介绍的内容全部由已收录数据推导（地势等级、诗境、朝代与题材构成、代表篇目），
> **不编造地理描述** —— 数据里没有的东西宁可不说，也不写一段「地处……自古以来……」的套话。

### 四、诗人行迹（16 条路线）
李白、杜甫、苏轼、王维、孟浩然、白居易、韩愈、辛弃疾、陆游、刘禹锡、杜牧、王昌龄、岑参、王安石、范仲淹、李清照。
按时间顺序连成 3D 弧线飞路，带编号站点牌与流动光点，可逐站点开查看创作背景与年份。

**选中一位诗人后，每个行迹地点会挂一个「气泡卡片」**——上面是站名 + 年份，下面是这位诗人在此地所作的代表作（一首，多则 `+N`）。
气泡背景半透明（`rgba(0.62)` + 12px backdrop-blur），鼠标 hover 时变深——既看得见下面的地图地形，文字又能稳稳看清。
气泡用一条带尾巴的引线指回自己的锚点，多个气泡之间自动避让互不重叠。
没在他常驻的地点留下存世作品的（如李白的扬州与幽州台），气泡会显示「此行未见存世诗作」，而不留一片空白让人误以为加载失败。
想看这位诗人在此地的全部作品 → 点气泡里的地名飞过去，右栏的诗词详情视图就是全诗 + 注释 + 翻译。

**行迹面板右上有「气泡」开关**（金色圆点 = 显示；圆点变灰 = 隐藏）—— 看完信息想拿一张干净地图讲路线时点一下，整层气泡立即收起；再点恢复。
状态会跨诗人 / 退出行迹保留。
键盘可达：Tab 进入行迹面板后，焦点在「✕」上按 `Shift+Tab` 即可到「气泡」开关；`Enter` / `Space` 都能触发。

> 气泡属于「地图上的文字标注」，与「地名」开关绑在一起：老师想拿一张干净的
> 地图上课时，关掉「地名」就同时把气泡也隐了。

**选中一条行迹后，地图只保留这条行迹上的站点**，其余光柱与标注全部隐藏，左侧列表同步收窄。
不这么做的话，79 根光柱会和行迹线叠成一片，路线走向完全看不出来。

### 五、课堂练习（三种题型，自动出题）
| 题型 | 玩法 |
| --- | --- |
| **看图识诗** | 给出诗句，**直接在 3D 地图上点出它的诞生地**，或从四个选项中作答 |
| **补全诗句** | 给出上句，四选一补下句，即时给出出处与所属诗境 |
| **飞花令** | 随机令字（月 / 江 / 山 / 风 / 花 / 雪…），限时接句，自动校验并标注出处 |

### 六、课堂演示
- **自动巡游**：按当前筛选结果依次飞往各诗境，自动朗读，底部显示进度与篇目。支持范围切换：全部 / 唐诗之路 / 宋词之境 / 边塞烽烟 / 江南水乡。
- **朝代时间轴 + 题材 + 地域**三重筛选，地图光柱与列表实时联动。
- **左右抽屉都可收起**，把画面让给地图；收起后屏幕边缘会留一个带竖排文字的醒目按钮，随时点开。

> 朝代筛选按**站点覆盖的朝代集合**匹配，而非只看站点主朝代。一处诗境往往横跨数代
> （西湖既有白居易的唐音，也有苏轼的宋调，还收于谦、龚自珍），若只按主朝代判断，
> 「元明清」会变成永远点不出东西的死选项。站点集合由 `site.era` 并上其全部诗篇的
> `dynasty` 映射结果得出，映射规则见 `js/data/poetry.js` 的 `DYN_ERA_RULES`。
>
> **虚拟专题站点例外**：带 `virtual: true` 的站点（如「课内诵读」）只匹配自身那一档，
> 不并入各朝代档——它收了唐宋元明清各代的篇目，若照常并入，就会在每一个朝代筛选里
> 都冒出来，把地理筛选搅浑。同理，看图识诗也不会把虚拟站点当作答案或选项，
> 因为这些篇目本来就没有「诞生地」。

### 七、窄屏与键盘

**窄屏（≤860px）下两栏是互斥的覆盖式抽屉。** 地图始终是整幅的，两栏盖在它上面；
点抽屉以外的遮罩、或按 `Esc`，都能收起抽屉。打开一边会顺手收起另一边。

> 并排布局在手机上本来就装不下：390 宽时两栏各占约半屏，地图只剩约 40px 可见 ——
> 「看地图」这件事本身没了。这不是宽度没调好，是形态不对。
> 抽屉宽度取 `min(340px, 100vw - 48px)`，总在另一侧留出 ≥32px 的地图缝隙。

**键盘可以完整操作：**
- 顶栏 → 侧栏 → 底部工具条 → 列表，Tab 顺序与视觉顺序一致；收起的面板**不会**出现在 Tab 顺序里。
- 焦点环用 `:focus-visible`，键盘操作时每个控件都有明确的焦点指示。
- 左栏诗境列表、行迹列表与站点、搜索结果都是可聚焦的，`Enter` / `空格` 即选中。
- 搜索框内 `↑` `↓` 在结果之间移动，`回车` 跳往当前项。
- 诗词详情弹窗打开时焦点移入弹窗、`Tab` 被关在弹窗内，关闭后焦点归还给打开它的那个控件。
- 文档最前面有一条**跳转链接**（`跳到底部工具条`）。左栏有 79 个诗境条目，键盘用户想到底部
  要按几十次 Tab；它平时用 `transform` 移出视野，只在 Tab 到它时才滑下来，鼠标用户看不到。
- `Esc` 由内向外逐层关闭：诗词弹窗 → 区域诗词条 → 窄屏抽屉 → 练习卡 → 行迹模式。

**列表项的可访问名。** 诗境 / 行迹 / 行迹站点 / 搜索结果都写了 `aria-label`。
这里要说明动机 —— 不是因为「不写的话读屏念得太长」：实测可见文本都很短
（`.site-row` 只有「碣石秦皇岛」5 个字）。问题在另一侧：**可见文本相对完整信息是有损的**，
省份被 `sub.split('·')` 截掉只剩城市，列表标题给的「诗境」这个类别读屏聚焦到行上时不会回头念。
所以 `aria-label` 在这里是**补回视觉上由排版和图标承担的信息**，不是给长文本做摘要。

**移动端触摸。** 单指旋转、双指缩放由 OrbitControls 原生提供（`touches = { ONE: ROTATE, TWO: DOLLY_PAN }`），
不需要自己写。真正要改的只有 viewport 那条 `maximum-scale=1` —— 它会禁用浏览器缩放，
对弱视用户是硬伤，已去掉。

**归属策略**：有可靠地理出处的篇目归入对应诗境（《寒食》→长安、《望海潮》→西湖、《燕歌行》→山海关、

归入「课内诵读」专题，不为凑数硬编一个出处。

node tools/coverage.mjs          # 摘要 + 缺失清单
node tools/coverage.mjs --full   # 额外列出已覆盖篇目及其所在诗境

## 操作说明

| 操作 | 效果 |
| --- | --- |
| 拖动 / 滚轮 / 右键拖动 | 旋转 / 缩放 / 平移（2D 模式下锁定旋转，只平移缩放） |
| **点击地图上的省域** | 右侧显示该地区介绍，底部弹出该地区的诗词列表 |
| **点击底部诗词卡片** | 弹出该首诗词的详情弹窗 |
| 点击光柱或地名标签 | 打开该诗境的诗词面板并飞往该地 |
| 点击屏幕左 / 右边缘的竖排按钮 | 展开 / 收起左右抽屉（窄屏下两栏互斥，打开一边会收起另一边） |
| 点击抽屉以外的遮罩（窄屏） | 收起抽屉 |
| `空格` | 开始 / 暂停巡游 |
| `←` `→` | 上一处 / 下一处诗境 |
| `1` `2` `3` | 切换 探索 / 行迹 / 课堂 |
| `R` `T` | 复位视角 / 俯视 |
| `Tab` / `Shift+Tab` | 在控件之间移动焦点（收起的面板不在 Tab 顺序里） |
| `Enter` / `空格` | 激活当前聚焦的列表项（诗境 / 行迹 / 搜索结果） |
| `↑` `↓`（搜索框内） | 在搜索结果之间移动 |
| `Esc` | 由内向外逐层关闭：诗词弹窗 → 区域诗词条 → 窄屏抽屉 → 练习卡 → 行迹模式 |

搜索结果框的关闭方式：点击页面任意空白处（地图 / 左右面板）、点击结果项、清空输入框、点击清空按钮、按 `Esc`，均可关闭。
按 `回车` 则直接跳往第一条结果并关闭结果框。

├── tools/e2e-a11y.mjs      键盘可访问性回归 runner：发真实按键量 Tab 顺序与焦点（22 项）

## 技术要点

- **投影**：Albers 等积割圆锥，`lonLatToWorld` / `unprojectToLonLat` 双向换算，HUD 经纬度即由此得出。
- **地形**：GeoJSON 环形 → 归一化绕向 → `THREE.Shape`（外环 + 内洞）→ `ExtrudeGeometry` → `rotateX(-90°)`，
  挤出高度按各省平均海拔映射，顶面/侧面双材质，边界线单独绘制在顶面之上。
- **相机**：30° 窄视角（长焦）模拟近似轴测，抑制大幅地图的透视畸变。
- **取景**：`frameView()` 负责把地图框进左右面板之间的「可视空白区」。
  界面占位由 `measureInset()` 直接读真实 DOM，因此随窗口尺寸与响应式布局自适应。
  取景距离不用解析式估算——相机斜视时靠近相机的一侧会因透视被放大，估算会低估横向占宽、
  导致版图被面板压住；改为把「地形顶点抽样 + 41 根光柱柱顶」投影到屏幕实测包围盒，
  迭代收敛距离，再把包围盒中心对齐到空白区中心（横向取负号、纵向取正号，
  因为屏幕 y 轴向下而相机 up 轴向上）。窗口尺寸变化时，若用户未手动调整过相机、
  未选中具体诗境且无补间在跑，会自动重新取景。
- **拾取**：先射线检测光柱柱体，再在命中的候选中取「屏幕距离最近」者，避免前排站点遮挡后排。
- **后期**：UnrealBloomPass + OutputPass（ACES 色调映射）。
- **性能**：所有贴图程序化生成（径向光晕、云海），无外部图片；地图数据抽稀至 1.7 万点。
- **显隐统一走 `.hidden` 工具类**：`css/style.css` 顶部定义了 `.hidden { display: none !important; }`，
  所有弹层（搜索下拉、练习卡、行迹面板、悬浮提示）只靠这一个类控制显隐，组件不再各写一条
  `.xxx.hidden` 规则。**注意 `!important` 不能省**——各组件自身都定义了 `display`，
  同特异度下后出现的规则会盖掉普通的 `.hidden`，导致 JS 加了类元素却依然可见。
  `tools/validate.mjs` 的第 10 项检查会静态校验这一点。
- **诗篇标签栏限高**：`.poem-tabs` 设了 `max-height: 56px; overflow-y: auto`。
  诗篇多的站点（长安 13 首、课内诵读 77 首）标签会排成好几行，不限高就会把正文挤出视野。
- **教材扩容批独立成文件**：`js/data/poems-textbook.js` 里每条诗带一个 `site` 字段，
  由 `js/data/poetry.js` 在聚合时按站点分桶并入。这样 233 篇教材篇目集中在一处、便于与
  `tools/textbook-list.mjs` 对照核对，而不必散落到各个 `sites-*.js` 里去找位置。
- **2D 模式不换相机**：版图是用 `ExtrudeGeometry` 挤出的水平顶面，从正上方俯视时顶面本身没有
  透视畸变、侧壁又被自身遮住 —— 视觉上与一张平面地图等价。所以 2D 只做三件事：
  正上方取景（`VIEW.flat`）、收起三维装饰（光柱 / 云海 / 星空 / 泛光）、锁定旋转。
  光柱收起后改用放大后的地面光圈作为落点标记（竖直圆柱从正上方看只剩一个点，看不见柱身）。
  这样不必维护第二台相机、第二套控制器和两套取景逻辑。
- **抽屉开关必须放在面板外面**：面板收起靠 `transform: translateX()`，而 transform 会给后代
  建立新的包含块 —— 开关若留在面板内部会跟着平移出屏（左栏只剩 5px、右栏几乎完全出屏），
  用户就再也找不到展开按钮。现在开关是 `<body>` 下的 `position: fixed` 元素，位置由
  `syncPanelToggles()` 按面板实际宽度算出，因此各响应式断点都不用单独写媒体查询。
  `tools/validate.mjs` 第 12 项会静态拦截「开关又跑回面板里」。
- **省份 → 诗词的索引**：`PROVINCE_SITES` 在启动时按 `provinceAt(site.lon, site.lat)` 把 79 处诗境
  分桶到省级行政区。用与光柱落点完全相同的判定，保证「点那根光柱」和「点那个省」得到一致结果。
  点省份时先射线检测省域网格（`map.hoverTargets`），命中后再查这个桶。
- **拾取优先级**：点击是「先光柱、后省域」。光柱的拾取体是竖直圆柱，斜视角下投影成一条又高又窄的
  竖条，所以判断「某点离光柱多远」要看**水平**距离而不是直线距离。
- **同一件事的多个侧面必须一起复位**：地图光柱、左侧诗境列表、右栏地区介绍、底部区域诗词条
  这四个侧面同源于「当前可见的诗境集合」。各自更新就会打架 —— 点开四川省看到 4 处诗境，
  再切到李白行迹（地图只剩行迹那 9 站，四川省内只剩峨眉山），右栏却仍列着 4 处，
  用户照着清单去地图上找，根本找不到。现在统一挂在 `applyVisibility()` 末尾的
  `refreshRegionPanel()` 上：可见性一变，四个侧面一起重算（筛选、行迹聚焦、进出练习都走这条路）。
  右栏用 `#detailBody.dataset.region` 记住「当前展示的是哪个地区」，显示诗境详情时该标记被清除，
  所以改筛选不会把用户正在看的诗境详情替换成地区介绍。
  退出行迹 / 练习模式时，被收起的底部诗词条会跟着回来（`refreshRegionPanel({ showBar: true })`）。
- **浮层不会自动避让，必须显式让位**：所有浮层都是 `position: fixed`，浏览器只按 z-index 叠，
  不会替你腾位置。底部诗词条（z 44、居中 980 宽）曾压住右栏 180px 宽（「代表篇目」被切掉）、
  左栏 55px、行迹面板 8.5k px²；右下角显示经纬度的 HUD（z 30）更是 **100% 落在右栏（z 35）底下**，
  只透过玻璃背景显出一层灰影。修法是拿一个 body 类当「让位开关」：`body.rb-open` 时把
  左右两栏、行迹面板、HUD 的 `bottom` 一起抬高，`body.quiz-open` 时藏掉 HUD
  （练习卡居中在底部，会整个压住它）。诗词条与练习卡的高度由 JS 实测写进 `--rb-h` / `--qc-h`
  （空状态与有卡片时高度不同、题目与反馈区还会让卡片忽高忽低，写死会露馅；
  练习卡那条用 `ResizeObserver` 盯着，免得逐个渲染路径去补测量时漏掉一条）。
  让位的方向也要选对：**能竖向让就别横向挤**。练习卡一度被写成「挤在两侧栏之间」
  （`width: calc(100vw - 左栏 - 右栏 - 24px)`），390 宽时两栏各占 ~50vw，这个减法算出**负数** ——
  而 CSS 的 `width` 不接受负值，整条声明在计算值阶段失效、卡片回退成 shrink-to-fit，
  实测只剩 163px：文字竖排成一列、高度反涨到 468px。现在卡片只受视口约束
  （`min(560px, 100vw - 24px)`），侧栏改为整体上移。
  注意让位规则要覆盖**所有**同位置的浮层 —— 行迹面板是独立类 `.route-panel`、不在 `.panel` 里，
  漏掉它就成了「行迹模式下点省份，诗词条压住站点列表」。
  这类问题数据层和 DOM 结构都看不出异常，只能量 `getBoundingClientRect()` 交集，
  所以回归里有一条通用重叠检测（`tools/e2e-region.js` 的 `recNoOverlap`）。
- **一个回调不要承载两件事**：`onQuizMode(on)` 的语义是「地图全亮、等用户点省份作答」，
  只有看图识诗需要 —— 补全诗句和飞花令是拿 `onQuizMode(false)` 来开题的。
  早先这里顺手把 `body.quiz-open`（= 练习卡打开了）也挂在同一个参数上，于是后两种题型
  练习卡开着却没有 `quiz-open`：HUD 不隐藏（实测被压 17.6k px²）、侧栏不让位，
  退出逻辑还会把刚收起的诗词条又拉回来（卡片×诗词条重叠 95k px²，整条被盖住）。
  现在拆成 `onQuizMode` 与 `onQuizCard` 两个回调，各自对应一件事实。
  教训：**当某个回调的参数开始需要「有时候也代表另一件事」时，就是该拆的信号**；
  这种错误在宽屏上未必看得出来（卡片 560 宽、位置又巧），是窄屏巡检顺出来的。
- **窄屏形态不是「把宽度调小」，是换一种布局**：≤860px 时两栏从「并排的常驻工具」
  改为「互斥的覆盖式抽屉」（`body.narrow` 由 `ui.js` 维护，与 css 同一来源）。
  三件事必须一起做，少一件都不成立：
  1. **互斥**（`setPanelHidden` 里展开一边就收起另一边）——否则 390 宽下两个 340px 的
     抽屉同时铺开，总宽 680px，比修复前更糟；
  2. **取景不占位**（`measureInset` 在窄屏直接返回 0）——抽屉盖在地图上、不占版面，
     若照常按面板宽度留白，`frameView` 会把地图挤进「抽屉之外的那条缝」里；
  3. **遮罩**（`#drawerScrim`，z-index 34）——抽屉要盖住的是**地图**，不是整个界面，
     所以遮罩压住 `#stage` 却压在顶栏 / 底栏 / 诗词条 / 练习卡之下。
  另外**跨过断点时要成对处理**：进入窄屏两栏都收起，离开窄屏要把它们恢复展开 ——
  只做前一半的话，手机横竖屏一切换就留下一张空荡荡的地图加两个不起眼的小箭头。
- **新规则会把旧规则的某一条属性顺手吃掉**：让位规则写作 `body.rb-open .panel`（特异度 0-2-1），
  窄屏形态规则写作 `body.narrow .panel.left`（0-3-1）—— 后者更高，会把 `bottom` 一并盖掉，
  于是窄屏下抽屉不再给底部诗词条和练习卡让位，实测重叠 56.5k / 96.5k px²。
  修法是把窄屏下的让位**重写一遍**（`body.narrow.rb-open .panel`），而不是去调旧规则的顺序。
  教训：**加一条更高特异度的规则时，要连同它「顺带覆盖掉的其他属性」一起补上** ——
  宽屏上完全看不出异常，只有窄屏巡检量交集才暴露。
- **键盘可用性有三处最容易整片丢失**，且都不是「少写一个 aria 属性」这种小问题：
  1. **全局 `outline: none`**。原先 `button, input, select { outline: none }` 一句抹掉所有焦点环，
     鼠标用户毫无感觉，键盘用户则完全不知道焦点在哪 —— 按 Tab 屏幕毫无变化，等于界面不可用。
     改用 `:focus-visible`（只在非指针方式获得焦点时匹配，鼠标点击不会凭空多出一圈金框）。
  2. **收起的面板仍可聚焦**。收起只靠 `transform: translateX()` 平移出屏幕，元素还在文档流里、
     还在 Tab 顺序里，焦点会一路跑到屏幕外那些看不见的按钮上。补 `visibility: hidden`
     （配一个等于动画时长的 `transition-delay`，滑动过程不受影响）让整棵子树退出 Tab 顺序。
     **不能用 `display: none`** —— 那会连滑动动画一起丢掉。
  3. **模态弹窗不接管焦点**。打开时把焦点移入、`Tab` 困在弹窗内、关闭时归还给触发元素，
     三件缺一不可；否则焦点会掉回 `<body>`，下次 Tab 又从页面开头重走一遍，等于丢了位置。
  另外，`div` + `onclick` 的列表项（诗境 / 行迹 / 搜索结果）键盘**完全够不到**，
  统一用 `keyboardActivate()` 补 `tabindex` / `role` / `Enter`·`空格`。
  没有把它们改成 `<button>`：这些类挂着大量布局样式（flex 行、`margin-left: auto` 推右端、
  多行截断），换成 button 会连带吃到 UA 默认的背景色与对齐，回归面大得多。
  `空格` 必须 `stopPropagation` —— 全局快捷键把空格当「开始 / 暂停巡游」，
  而那个处理器只排除了 `INPUT` / `SELECT`，div 上的空格会一路冒泡上去。

### 数据校验

改动诗词数据后请运行校验脚本，确保不会破坏检索与出题：

```bash
cd poetry-3d-map
node tools/validate.mjs     # 全绿输出「✅ 全部校验通过」
node tools/coverage.mjs     # 教材覆盖率应为 100%
```

校验覆盖 12 类规则：

1. 字段完整性 —— 含**站点经纬度不得重合**（重合的两个站点在三维场景里会叠成同一根光柱，看起来少了一处诗境）
2. 诗篇逐条（联数与译文数一致、**意象字必须是单字且真实出现在正文中**、朝代可映射）
3. 标点规范（句末标点可被右引号包住；近体诗另要求上句以逗号收、中间各联下句以句号收）
4. **朝代筛选覆盖（检测死选项）**
5. 朝代分布
6. 行迹站点引用
7. 自动出题（选项无重复且含答案、飞花令例句充足）
8. 检索
9. 统计一致性
10. **`index.html` 中每个带 `hidden` 类的元素，都必须有 CSS 规则真正把它隐藏**
11. **教材扩容批归属** —— `poems-textbook.js` 里每条 `site` 都必须指向真实站点，且该诗确实被聚合进了那个站点
12. **抽屉开关位置** —— `.panel-toggle` 不得出现在 `.panel` 内部

> 第 10 项踩过的坑：JS 反复给搜索下拉加 `hidden` 类、类也确实加上了，但 CSS 里漏写
> `.search-results.hidden`，于是下拉框永远关不掉。**教训是验证界面状态必须断言渲染结果
> （`getComputedStyle(el).display === 'none'`），而不是断言类名（`classList.contains('hidden')`）
> ——类名是意图，渲染结果才是事实。**
>
> 第 11 项踩过的坑：`site` 写错时诗篇会被静默丢弃（分桶后没人来取），从数据层看不出任何异常。
>
> 第 12 项踩过的坑：开关原本是 `.panel` 的子元素，面板靠 `transform: translateX()` 收起时
> 把它一起带出了屏幕，用户「收起后找不到展开按钮」。CSS 与数据层都看不出异常，
> 只有到浏览器里点一次才暴露。
>
> 意象字若写成了正文里不存在的字（如把「芙蓉」记作「花」、把「蜡炬」记作「烛」），
> 详情页的意象字标签就会指向空结果；校验脚本会直接拦截这类错误。
> 近体诗（绝句 / 律诗）要求两句一联；词、散曲、古体诗、乐府、楚辞、歌行的一个「组」
> 是一个句读单元，内部可含多个逗号分句（如《念奴娇》「大江东去，浪淘尽，千古风流人物。」），
> 但组内最多放两个字符串。

### 界面回归（浏览器端）

静态校验只能保证数据自洽，界面行为要在真浏览器里跑。`tools/` 下有三个注入脚本，
外加三个 runner 各回答一个问题：

```bash
cd poetry-3d-map
python3 serve.py &                  # 先起静态服务器
node tools/e2e-all.mjs              # 功能回归：一个视口（1440×900）跑三套注入脚本
node tools/e2e-layout.mjs           # 布局巡检：八个视口量重叠 / 溢出 / 元素宽度
node tools/e2e-a11y.mjs             # 键盘回归：发真实按键量 Tab 顺序与焦点
node tools/e2e-bubbles.mjs          # 气泡层回归：16 条行迹逐条量气泡数 / 不重叠 / 不出界 / 有内容
```

**为什么不是一套**：它们回答的是四个不同的问题 ——
`e2e-all.mjs` 问「功能对不对」，`e2e-layout.mjs` 问「摆得下吗」，
`e2e-a11y.mjs` 问「键盘能不能用」，`e2e-bubbles.mjs` 问「**站点多 → 塞得下吗**」。
混在一起跑会得到一个误导性的绿灯：功能全对、布局全错，而报告只写「全部通过」。
布局类缺陷只在特定宽度才出现，1440 下量什么都是对的；
键盘类缺陷则只有**发真键**才测得出来（见下）；
气泡类缺陷则只有**每条行迹都跑一遍**才测得出来 ——「李白 9 站能撑开」不保证「杜牧 6 站也能」。

`e2e-all.mjs` 会在**每套脚本跑之前重新导航页面**，保证脚本之间零状态污染。这不是洁癖，
是踩出来的：三套脚本共用同一个浏览器会话，而 `e2e-scene.js` 第 12 段会把 `#viewGroup` 里
所有视角按钮都点一遍（含后来新增的「2D 平面」），跑完页面就停在 `flat-mode`；紧接着跑的
`e2e-region.js` 里「切 2D」系列断言就会因为 `setFlatMode(on)` 开头的
`if (state.flat === on) return` 直接早退而**全部假失败**，看起来像功能坏了，其实只是状态脏了。

修复分两层：`e2e-scene.js` 跑完主动退回 3D（**治本** —— 实测只做这一步，连跑就已全绿），
以及 `e2e-all.mjs` 每套前 reload（**结构性保险** —— 以后新增脚本忘了复位也兜得住）。

手动单跑某一套时：

```bash
agent-browser open http://127.0.0.1:8777/
agent-browser eval "$(cat tools/e2e-region.js)"
agent-browser close
```

| 脚本 | 覆盖 |
| --- | --- |
| `e2e-search.js` | 搜索下拉框 10 条关闭路径 + 新增的「课内诵读」朝代 / 主题 / 地域筛选（20 项） |
| `e2e-scene.js` | 3D 地标数与位置、详情面板全量渲染 245 首诗篇、竖横排切换、三种练习、巡游、行迹、图层与视角、跑完复位回 3D（53 项） |
| `e2e-region.js` | 抽屉开关收起后仍可见可点、点击省份 → 地区介绍 + 底部诗词条、诗词详情弹窗（内容完整性 + 3 条关闭路径）、2D 平面切换、行迹聚焦只留本行迹站点、地区介绍与诗词条跟随可见性同步、浮层互不遮挡、三种练习的卡片布局与让位（92 项） |

三个脚本都以「渲染结果」为准：判定弹层关闭看 `getComputedStyle(el).display === 'none'`，
判定详情面板渲染看 `#detailBody .poem-body .vline` 的实际条数是否等于该诗的行数，
判定抽屉开关可用看 `getBoundingClientRect()` 是否与视口有交集（而不是看它有没有某个类）。

### 键盘回归（必须发真实按键）

`e2e-a11y.mjs` 是一个 **Node runner**，不是注入脚本 —— 因为「焦点可见」与「Tab 顺序」
这两件事**只有真实按键才测得出来**：

- `:focus-visible` 匹配与否，取决于浏览器认定的「最近一次输入方式」。在页面里 `el.focus()`
  属于程序化聚焦，浏览器不认；用它去断言 `:focus-visible` 会得到假阴性 ——
  明明鼠标点不出焦点环、键盘点得出，脚本却两边都测成一样。
- Tab 顺序是浏览器的默认行为。用 `dispatchEvent` 造一个 `keydown` 出去，浏览器不会替你移动焦点，
  测出来的永远是「焦点没动」。

所以它用 `agent-browser press Tab` 发真键，每按一次回页面里问一句「现在焦点在谁身上」，
断言的是 `document.activeElement`、它的 `outlineStyle`、以及它是不是真在某个可见容器里。共 22 项：

| 分组 | 覆盖 |
| --- | --- |
| 宽屏 Tab 顺序 | 首个 Tab 落在搜索框；顶栏之后进入侧栏内容（而非跳过侧栏直奔边缘开关）；每一站都有可见焦点环 |
| 窄屏 Tab 顺序 | 收起的两栏不出现在 Tab 顺序里；抽屉开关本身仍可 Tab 到；**负向对照**：打开左栏后其内容必须重新可聚焦（否则「收起来够不到」也能靠「一律隐藏」蒙混过关）；遮罩出现与点击收起 |
| 弹窗焦点 | 焦点移入弹窗；连按 8 次 Tab 不逃出；Esc 关闭后焦点归还触发元素 |
| 列表项键盘激活 | 诗境列表项 `tabindex` / `role`；`Enter` 选中的正是该项；列表项上的空格**不会**顺手触发巡游；搜索框 `↓` 把焦点交给结果项 |

> 两个踩过的坑：
>
> 1. **`blur()` 不能把 Tab 起点复位。** blur 之后 `activeElement` 确实变回 `<body>`，
>    但浏览器记着「顺序焦点导航的起点」，下一次 Tab 仍从刚才那个元素往后走。
>    于是「点击开关 → blur → Tab」会直接从开关的下一个元素开始，跳过它前面的整个左栏，
>    看起来像「左栏内容不可聚焦」，其实只是没从头走。可靠的办法是一路 Tab 回到已知的第一站。
> 2. **`agent-browser eval` 的返回值是「JSON 文本」**。若页面里返回的已经是一个 JSON 字符串，
>    拿到的就是带引号的 JSON 字符串，`JSON.parse` 一次得到的是**字符串**而非对象 ——
>    spread 出来全是下标键，所有字段读出来都是 `undefined`，表现为「脚本在跑、断言全错」。
>    要再解一层。

### 布局巡检（多视口）

`e2e-layout.mjs` 在**一组**视口里各跑一遍 `e2e-layout.js`，量的是几何而非行为：

| 检查 | 口径 |
| --- | --- |
| 浮层互相遮挡 | 两两求 `getBoundingClientRect()` 交集，必须为 0 |
| 让位过度 | 让位后侧栏高度 < 190px、诗词条宽 < 240px 也算失败 |
| 练习卡宽度 | **不变量**：必须正好等于 `min(560px, 100vw - 24px)` |
| 横向溢出 | 只看自己不能滚的容器（`.bottombar` 是设计上就横向滚动的，跳过） |
| 右溢视口 | 元素右边缘不得越过视口 |
| **窄屏两栏互斥** | 窄屏下左右两栏不得同时可见（同时可见即「地图被夹成一条缝」的病根） |
| **窄屏抽屉留缝** | 抽屉宽度 ≤ `100vw - 48px`，总要在另一侧留出 ≥32px 的地图缝隙 |

视口刻意取在每个响应式断点的**两侧**（断点 1280 / 1080 / 860 / 640）：
`390 / 480 / 640 / 861 / 1024 / 1081 / 1281 / 1440`。
「某个宽度忘了覆盖」这类错误正好藏在断点右边的缝隙里 ——
`.panel.right` 在 ≤860 用了 `50vw` 约束而 `.panel.left` 漏了，390 宽下两栏同时展开
水平重叠 57px；而左栏在窄屏默认收起，只有专门造出「两栏全开」这个状态才复现得出来。
所以巡检里除了默认状态，还要**主动构造组合状态**（两栏全开 / 三种练习各一遍 / 行迹 + 点省份）。
窄屏下「两栏全开」这一步的含义变了 —— 它验的不再是「摆不摆得下」，而是**互斥到底有没有生效**
（两个开关都点过之后，必须恰好只有一栏处于展开状态）。

> **写这类脚本时踩过的三个坑，值得记下来：**
>
> 1. **别用「省域中心」当点击点。** 三维浮雕地图里各省台面高度不同，射线可能先打中更近 / 更高的邻省
>    （甘肃是狭长弧形，其中部会被海拔更高的青海台面挡住）。脚本必须用与主程序相同的射线逻辑
>    复核「这个屏幕点实际落在哪个省」，并在省内多取几个候选点。
> 2. **判断「离光柱多远」要只看水平距离。** 光柱是竖直圆柱，斜视角下投影成一条又高又窄的竖条；
>    用直线距离会挑到「直线 56px、水平仅 4px」的点，点击被光柱的拾取圆柱吃掉，测不到省份分支。
>    最稳妥的做法是直接调 `window.__app.pickBeacon({clientX, clientY})` 问主程序会不会被截走。
> 3. **脚本之间必须隔离，每套前 reload。** 见上文 —— 假失败的典型长相就是「单独跑全绿、连跑就挂」。
>    遇到这种症状先怀疑状态污染，别急着改产品代码。
