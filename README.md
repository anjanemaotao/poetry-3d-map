# 诗境 · 山河

> 中国古典诗词三维地图教学系统 —— 基于 Three.js 的 3D 交互式古诗教学工具

把 79 处诗境、245 首名篇、1647 句诗文放在一张可以旋转、缩放、点选的立体中国地图上。
每处光柱都是一首诗，每条江河都是一堂课。

**教材覆盖**：统编版小学 108 首 + 初中 84 首 + 高中新课标诗词曲 41 首，共 233 篇，**覆盖率 100%**。

## 快速开始

ES Module 无法在 `file://` 协议下加载，请用附带的本地服务器启动。

**方式一：双击图标（推荐）**

| 双击 | 作用 |
|---|---|
| `启动.command` | 启动服务，就绪后自动打开浏览器（默认 `http://127.0.0.1:8777`） |
| `停止.command` | 停止服务（按 pid 文件停，再用端口兜底） |

两个脚本都**幂等**：服务已在跑时再点「启动」不会起第二个进程，直接开页面；
服务没跑时点「停止」只提示一句，不报错。

服务**脱离终端运行**（两级 fork + `setsid`）—— 关掉那个终端窗口不会把服务带走。
`start.command` / `stop.command` 是同一套逻辑的英文名入口，命令行调用二者完全等价
（中文名脚本只是转调它们，不复制逻辑，免得两份迟早改歪）。

**方式二：命令行**

```bash
cd poetry-3d-map
./启动.command              # 或 ./start.command，默认 8777
./启动.command 8080         # 换端口
./停止.command              # 或 ./stop.command，可带端口参数
```

**方式三：前台直接跑**（日志直接打在眼前，`Ctrl+C` 停止）

```bash
python3 serve.py            # 默认 http://127.0.0.1:8777，会自动打开浏览器
python3 serve.py 8080       # 指定端口
```

打开后即可使用，**无需联网**（Three.js 与地图数据已全部本地化）。
后台方式启动的日志写在 `.server.log`，进程号记在 `.server.pid`。

## 启动失败怎么办

加载页**不会无提示地一直转下去**。页面在模块加载前就装了兜底脚本（`index.html` 顶部）：

- 捕获全局运行时错误与模块加载失败，把原因直接显示在加载页上；
- **18 秒看门狗**：超时未启动会报出「最后停在哪一步」（构建三维地形 / 加载诗词数据 / 生成地势起伏 / 点亮诗境地标 / 装配界面与题库）；
- 进入页面前先做 **WebGL 预检**，显卡或浏览器禁用 WebGL 时给出明确提示；
- 无论哪种失败，都提供「重新加载」与「先进入页面」两个出口。

进度条是**真进度**（由主程序分阶段上报），不是无限滑动的假动画——假动画看不出「在动」还是「卡死」。

常见原因对照：

| 加载页显示 | 原因 | 处理 |
| --- | --- | --- |
| `Failed to fetch dynamically imported module` | 直接双击 `index.html`（`file://`），或没走本地服务器 | 用 `python3 serve.py` 启动 |
| `无法创建 WebGL 上下文` | 浏览器禁用了硬件加速 / 显卡驱动异常 | 开启硬件加速，或改用 Chrome / Edge |
| 停在某一阶段超过 18 秒 | 网络或磁盘较慢，模块（约 2 MB）没加载完 | 检查网络后点「重新加载」 |
| `当前浏览器过旧` | 不支持 ES Module | 换新版浏览器 |

> 本应用使用 `<script type="importmap">` 解析 `three` 这一裸模块名（Three.js 官方推荐做法，
> `vendor/jsm/**` 内部也是以 `from 'three'` 互相引用的）。**请不要绕过 import map 去改 vendor 里的
> 引用路径** —— 那是 Three.js 的标准分发形态，改成相对路径会让日后升级 Three.js 变成手工活。

## 功能一览

### 一、三维诗境地图
- **中国标准 Albers 等积割圆锥投影**（中央经线 105°E，双标准纬线 25°N / 47°N），与国家标准地图一致。
- 版图要素完整：**台湾省、香港特别行政区、澳门特别行政区、南海诸岛（九段线）**全部按标准绘制，默认「全域」视角即可看到完整领土。
- 34 个省级行政区按**平均海拔挤出成 3D 地形**（青藏高原最高、东部平原最低），配色为「青绿山水 → 高原土黄 → 雪线」的高程设色。
- **长江、黄河、京杭大运河**以发光曲线示意，串起沿岸诗境。
- 悬停省份高亮并显示地势类型，右上角实时显示经纬度；**经纬度读数随缩放自动细化**（默认 2 位，拉近到 3 倍 / 8 倍时升到 3 位 / 4 位），放大后能读到 110m 级的坐标。
- **标记不随缩放变大**：光柱、地面光圈、行迹圆点与序号牌在屏幕上保持恒定大小，滚轮拉近只放大地图本身 —— 所以「放大看细节」是真放大，而不是连光柱一起放大、看起来跟没放大一样。向内可拉近约 14 倍（默认视角视域约 262km 宽 → 最近约 19km）。
- **2D 平面地图一键切换**（底栏「2D 平面」）：切到正上方俯视、压平地形、收起光柱与云海星空，并锁定旋转，得到一张干净的平面地图；再点一次回到 3D。
  - 2D 下的地点标记是**一个小圆点**（深色描边 + 朝代色填充，直径约 13px），不是三维里那圈又大又糊的地面光圈 —— 圆点和旁边的地名**都可以点**。
  - 地名标签改为**左对齐排在圆点右侧**（并有一小段渐隐引导线），不再压在地点正上方；这样地名既不会盖住圆点，也不会互相叠字。

> **2D 平面 / 3D 地势 / 地球 是「三选一」，不是三个独立开关。**
> 点其中一个会自动退出当前那个（`setViewMode` 是唯一入口）。早先三者各自维护自己的 on/off，
> 在地球模式下点「2D 平面」不会退出地球 —— 地球层与版图层同时可见、极角限制与近裁剪面互相打架，
> 画面变成一团谁也说不清的东西。

### 二、地球模式（太空视角）
底栏点「**地球**」，视角从「俯视一块版图」切到「从太空看一颗球」：

- **整颗地球的三维模型**：真实高程起伏 —— 青藏高原隆起、喜马拉雅山脊、马里亚纳海沟下陷都按实际高度挤出，不是一颗光滑的标准球。半径极差 0.0347（约 0.35% 的地球半径）。
- **全球地形按 ETOPO1 高程数据上色**：深海蓝 → 浅海青 → 平原绿 → 高原土黄 → 雪线白；半透明海壳压住海底起伏，让海岸线成为清晰的分界。
- **79 处诗境全部落在中国**：金色光点贴在中国版图上，一眼就能看出「诗词集中在中国」这件事。中国版图按中国标准地图数据叠加高亮与描边，**含台湾省、香港特别行政区、澳门特别行政区及南海诸岛（九段线）**。
- **鼠标拖动可朝任意方向转动地球**（极角放开到接近两极），**左键 / 右键都能拖动转动** —— 右键在版图上是平移，地球上的「移动」必须靠转动（target 恒为球心），所以右键在地球上被重定向为 `ROTATE`；滚轮缩放，缩放范围对应「一屏可见 164° → 12.6°」，即 13 倍放大。
- **默认视角自动把中国转到正面**（画面中心落在 104°E / 34°N），一进去就看见那簇诗境，而不是随机给一片大洋。
- **点地球上的任意一处诗境即可选中**：地球自动转到该地点正面朝前并拉近，右栏同步显示诗境详情。背面被球挡住的地标不会被误选中。
- **拉近到一定程度（相机到球心 ≤ 3.4 个地球半径，约一屏 88° 跨度）后，地名逐个冒出来**：默认太空视角下 79 处诗境挤在中国那一小片里，强行画出来只会互相压成一团黑，所以默认关、拉近才开；标签左对齐排在光点右侧 16px，与光柱顶端互不重叠。背面被地球挡住的地名自动剔除。
- **按 `Esc` 退出地球模式**（再点一次「地球」按钮也一样）；按 `R` 回到默认太空视角。
- **光点不随缩放变大**：与主地图同一条原则 —— 拉近只放大地球本身，79 个光点始终保持同样的屏幕尺寸，不会糊成一片。太阳光跟着相机走，看到的那一面永远是亮的，同时保留斜射光把山脊照出来。
- **行迹在地球上按球面重画**：选中一位诗人后，站点之间走**大圆航线**（slerp 插值），贴着地表飞（抬升上限 0.11 个地球半径），序号牌贴在每个站点正上方一点点。**不复用版图那套几何** —— 版图的弧线要抬 0.55~3.6 个世界单位（那里一个单位约 100km），放到半径 1 的球上就是 3.6 个地球半径高的巨型管子。
- 行迹取景按**视场角反解球面距离**（`d = R·cosθ + R·sinθ/tanφ`），保证整条行迹在横竖两个方向都装得下；序号牌也可以直接点。

> 全球底图**只画自然地理**（海陆分界与地形），**不画任何政治边界**；中国版图单独由中国标准地图数据叠加。
> 这样既避免引入境外数据源对中国领土要素的错误表达，又直接表达了「诗词集中在中国」。
> 地球是独立的一层，与「中国地势图」不共用任何几何，进出时两边互不干扰。

### 三、诗词教学主体
- **79 处诗境**：黄鹤楼、白帝城、赤壁、滕王阁、岳阳楼、庐山、西湖、泰山、玉门关、阳关、轮台、蓝关、儋州……
- **245 首诗篇**（先秦至清），每首包含：正文（竖排 / 横排一键切换）、逐联对照译文、词语注释、赏析、意象字、学段标注（小学 / 初中 / 高中必背）。
- **教材全覆盖**：统编版小学 108 首、初中 84 首、高中新课标诗词曲 41 首，共 **233 篇，覆盖率 100%**（见下文「教材篇目覆盖」）。
- **课内诵读专题**：教材中确实系不到具体地点的篇目（咏物、节令、哲理之作，或《诗经》《古诗十九首》这类难以落到一城一地的早期作品）集中收纳为一个非地理专题，不硬编出处。
- 支持**朗读**（浏览器语音合成，选中即诵）。
- 全文检索：按诗名、作者、诗句、地名、背景文字检索并一键飞往。输入后按 `回车` 直接跳往第一条结果。

### 四、点击地图区域 → 当地诗词
教学上最常用的入口：**单击地图上的任一省域**，即可看到「这一带出过哪些诗」。

1. **右侧抽屉**显示该地区介绍：地势类型、收录的诗境与诗篇数、朝代构成、题材分布、境内诗境清单、代表篇目。
2. **底部弹出区域诗词列表**：横向排列该地区的全部诗词卡片（含名句首行），可横向滚动。
3. **点击任一诗词卡片**，弹出**诗词详情弹窗**：正文竖排 / 横排、对照译文、词语注释、赏析、意象字一应俱全，与右侧抽屉里的详情完全同构。

> 地区介绍的内容全部由已收录数据推导（地势等级、诗境、朝代与题材构成、代表篇目），
> **不编造地理描述** —— 数据里没有的东西宁可不说，也不写一段「地处……自古以来……」的套话。

### 五、诗人行迹（16 条路线）
李白、杜甫、苏轼、王维、孟浩然、白居易、韩愈、辛弃疾、陆游、刘禹锡、杜牧、王昌龄、岑参、王安石、范仲淹、李清照。
按时间顺序连成 3D 弧线飞路，带编号站点牌与流动光点，可逐站点开查看创作背景与年份。

**诗人用抽屉式下拉选，不再平铺在面板里。** 16 位诗人平铺会占掉面板上半屏，把详情挤出视野；
现在面板头部是三行（标题 / 选择诗人 / 气泡开关 + ✕），选中的诗人名直接显示在按钮上。
下拉与搜索框的「巡游范围」共用同一套组件（`ui.bindDropdown`），键盘可达
（`role="listbox"` / `role="option"`、`aria-expanded`、Esc 关闭）。

**窄屏下选完诗人会自动收起行迹面板。** 面板在 390 宽下是 340px —— 占 87% 屏宽，
地图只剩 50px，用户「选了诗人却看不见行迹画在哪」，而行迹才是这一步的目的。
所以 `activate` 里判窄屏直接收起（`setRoutePanelHidden`），把地图让出来；
收起后左边缘留下一个 30×96 的「行 迹」开关，点一下就能把面板叫回来 ——
没有这个入口的话，用户想再看一眼行迹详情就只能退出行迹模式，等于「选了诗人反而回不去」。
宽屏两栏并排、地图仍占中间空白区，不存在这个问题，所以**不收起**
（`e2e-region.js` 有一条负向断言守着「宽屏不收」）。
状态复位有两个方向：进行迹模式时展开、退出时也展开 —— 只在进来时复位的话，
「选诗人 → 自动收起 → 退出 → 再进来」会看到一块空屏幕。

**三种视图各画一套**（切换视图时整条重建，不会把上一个坐标系的线留在屏幕上）：

| 视图 | 线路 | 序号牌 |
| --- | --- | --- |
| 3D 地势 | 逐段抬升的弧线飞路（越远抬得越高） | 悬在光柱顶端 |
| **2D 平面** | 抬到**最高站点之上**的一条**等高**折线（俯视下弧线不产生屏幕位移，只会偏离真实走向） | 贴地（抬升 0.12）、缩小到 0.72 倍，`depthTest: false` 压在地形之上 |
| **地球** | 站点间的**大圆航线**，贴地飞（抬升 ≤ 0.11 个地球半径） | 贴在站点正上方一点点（半径 +0.016），屏幕恒定约 27px、可点击 |

**选中一位诗人后，每个行迹地点会挂一个「气泡卡片」**——上面是站名 + 年份，下面是这位诗人在此地所作的代表作（一首，多则 `+N`）。
气泡背景半透明（`rgba(0.62)` + 12px backdrop-blur），鼠标 hover 时变深——既看得见下面的地图地形，文字又能稳稳看清。
**卡片停靠在地图左右两侧的空白带里**（不再压在地图上方），用一条带尾巴的引线指回自己的锚点：卡片按锚点横坐标对半分组（左半走左栏、右半走右栏），栏内按锚点纵坐标自上而下排开，空间不够时压缩间距而不重叠。
引线从卡片**朝向锚点那条边**出发 —— 横向能连就横向连；锚点横向正好落在卡片自己宽度范围内时（华东几个站点投影到右侧停靠带时会遇到）改用上/下边出线，避免一条金线横穿卡片。
没在他常驻的地点留下存世作品的（如李白的扬州与幽州台），气泡会显示「此行未见存世诗作」，而不留一片空白让人误以为加载失败。
想看这位诗人在此地的全部作品 → 点气泡里的地名飞过去，右栏的诗词详情视图就是全诗 + 注释 + 翻译。

**行迹面板右上有「气泡」开关**（金色圆点 = 显示；圆点变灰 = 隐藏）—— 看完信息想拿一张干净地图讲路线时点一下，整层气泡立即收起；再点恢复。
状态会跨诗人 / 退出行迹保留。
键盘可达：Tab 进入行迹面板后，焦点在「✕」上按 `Shift+Tab` 即可到「气泡」开关；`Enter` / `Space` 都能触发。

> 气泡属于「地图上的文字标注」，与「地名」开关绑在一起：老师想拿一张干净的
> 地图上课时，关掉「地名」就同时把气泡也隐了。

**选中一条行迹后，地图只保留这条行迹上的站点**，其余光柱与标注全部隐藏，左侧列表同步收窄。
不这么做的话，79 根光柱会和行迹线叠成一片，路线走向完全看不出来。

### 七、课堂演示
- **自动巡游**：按当前筛选结果依次飞往各诗境，自动朗读，底部显示进度与篇目。支持范围切换：全部 / 唐诗之路 / 宋词之境 / 边塞烽烟 / 江南水乡。
- **朝代时间轴 + 题材 + 地域**三重筛选，地图光柱与列表实时联动。
- **左右抽屉都可收起**，把画面让给地图；收起后屏幕边缘会留一个带竖排文字的醒目按钮，随时点开。

> 朝代筛选按**站点覆盖的朝代集合**匹配，而非只看站点主朝代。一处诗境往往横跨数代
> （西湖既有白居易的唐音，也有苏轼的宋调，还收于谦、龚自珍），若只按主朝代判断，
> 「元明清」会变成永远点不出东西的死选项。站点集合由 `site.era` 并上其全部诗篇的
> `dynasty` 映射结果得出，映射规则见 `js/data/poetry.js` 的 `DYN_ERA_RULES`。
>
> **虚拟专题站点例外**：带 `virtual: true` 的站点（如「课内诵读」）只匹配自身那一档，
> 不并入各朝代档——它收了唐宋元明清各代的篇目，若照常并入，就会在每一个朝代筛选里
> 都冒出来，把地理筛选搅浑。同理，看图识诗也不会把虚拟站点当作答案或选项，
> 因为这些篇目本来就没有「诞生地」。

### 八、窄屏与键盘

**窄屏（≤860px）下两栏是互斥的覆盖式抽屉。** 地图始终是整幅的，两栏盖在它上面；
点抽屉以外的遮罩、或按 `Esc`，都能收起抽屉。打开一边会顺手收起另一边。

> 并排布局在手机上本来就装不下：390 宽时两栏各占约半屏，地图只剩约 40px 可见 ——
> 「看地图」这件事本身没了。这不是宽度没调好，是形态不对。
> 抽屉宽度取 `min(340px, 100vw - 48px)`，总在另一侧留出 ≥32px 的地图缝隙。

**键盘可以完整操作：**
- 顶栏 → 侧栏 → 底部工具条 → 列表，Tab 顺序与视觉顺序一致；收起的面板**不会**出现在 Tab 顺序里。
- 焦点环用 `:focus-visible`，键盘操作时每个控件都有明确的焦点指示。
- 左栏诗境列表、行迹列表与站点、搜索结果都是可聚焦的，`Enter` / `空格` 即选中。
- 搜索框内 `↑` `↓` 在结果之间移动，`回车` 跳往当前项。
- 诗词详情弹窗打开时焦点移入弹窗、`Tab` 被关在弹窗内，关闭后焦点归还给打开它的那个控件。
- 文档最前面有一条**跳转链接**（`跳到底部工具条`）。左栏有 79 个诗境条目，键盘用户想到底部
  要按几十次 Tab；它平时用 `transform` 移出视野，只在 Tab 到它时才滑下来，鼠标用户看不到。
- `Esc` 由内向外逐层关闭：诗词弹窗 → 区域诗词条 → 窄屏抽屉 → 练习卡 → 行迹模式。

**列表项的可访问名。** 诗境 / 行迹 / 行迹站点 / 搜索结果都写了 `aria-label`。
这里要说明动机 —— 不是因为「不写的话读屏念得太长」：实测可见文本都很短
（`.site-row` 只有「碣石秦皇岛」5 个字）。问题在另一侧：**可见文本相对完整信息是有损的**，
省份被 `sub.split('·')` 截掉只剩城市，列表标题给的「诗境」这个类别读屏聚焦到行上时不会回头念。
所以 `aria-label` 在这里是**补回视觉上由排版和图标承担的信息**，不是给长文本做摘要。

**移动端触摸。** 单指旋转、双指缩放由 OrbitControls 原生提供（`touches = { ONE: ROTATE, TWO: DOLLY_PAN }`），
不需要自己写。真正要改的只有 viewport 那条 `maximum-scale=1` —— 它会禁用浏览器缩放，
对弱视用户是硬伤，已去掉。

## 技术要点

- **投影**：Albers 等积割圆锥，`lonLatToWorld` / `unprojectToLonLat` 双向换算，HUD 经纬度即由此得出。
- **地形**：GeoJSON 环形 → 归一化绕向 → `THREE.Shape`（外环 + 内洞）→ `ExtrudeGeometry` → `rotateX(-90°)`，
  挤出高度按各省平均海拔映射，顶面/侧面双材质，边界线单独绘制在顶面之上。
- **相机**：30° 窄视角（长焦）模拟近似轴测，抑制大幅地图的透视畸变。
- **取景**：`frameView()` 负责把地图框进左右面板之间的「可视空白区」。
  界面占位由 `measureInset()` 直接读真实 DOM，因此随窗口尺寸与响应式布局自适应。
  取景距离不用解析式估算——相机斜视时靠近相机的一侧会因透视被放大，估算会低估横向占宽、
  导致版图被面板压住；改为把「地形顶点抽样 + 41 根光柱柱顶」投影到屏幕实测包围盒，
  迭代收敛距离，再把包围盒中心对齐到空白区中心（横向取负号、纵向取正号，
  因为屏幕 y 轴向下而相机 up 轴向上）。窗口尺寸变化时，若用户未手动调整过相机、
  未选中具体诗境且无补间在跑，会自动重新取景。
- **标记不随缩放变大（缩放补偿）**：光柱、地面光圈、行迹圆点与序号牌是「标记」而非地理实体，
  屏幕尺寸不该随滚轮变化。透视投影下屏幕尺寸 ∝ 世界尺寸 / **深度**，所以只要让世界尺寸正比于深度，
  屏幕尺寸就恒定 —— 放大时地图变大、标记不变，放大才真的看得见细节。
  三个关键点：
  1. **逐站点补偿，不用统一系数**。标记的屏幕尺寸取决于**它自己**到相机的位置，而统一系数
     只能拿到「相机到 `controls.target`」的距离，两者仅在站点恰位于视野中心时才相等。
     用统一系数，中心处精确、偏出去的会一起缩（实测离中心 2 个世界单位的站点缩到 0.6 倍、
     远处缩到 0.47 倍）——而拉到最近正是最需要看清偏处细节的时候。
  2. **用「深度」而不是「直线距离」**。深度是相机朝向上的分量；偏离视轴 θ 的站点
     直线距离 = 深度 / cosθ，用直线距离补偿会多缩 1/cosθ（实测远端站点因此涨到 2.2 倍）。
  3. **所有硬编码的世界单位抬升都要跟着乘补偿系数**。光柱顶端序号牌、气泡锚点、
     点击吸附点、拾取柱体中点原本都写成固定世界高度；光柱缩了而它们没缩，
     气泡就会飘到序号牌上方近 90px 并挤在一起（实测「气泡之间互不重叠」因此报 5 对重叠）。
  基准取「默认取景时该站点自己的深度」，于是默认视角下每个站点的补偿系数都恒为 1，
  画面与引入补偿前逐像素一致。行迹管线是个例外：它的**长度**是地理量（不能缩）、
  **粗细**是标记量（要缩），共用一个 mesh 没法用 scale 分开，改为按补偿系数重建几何
  （只在变化超过 15% 时重建，避免缩放过程中每帧都换几何）。
  向内可拉近约 14 倍（`minDistance` 1.2，原为 5），视域 262km → 19km；
  拉到最近时若不加补偿，光柱屏幕高度本会涨 **15 倍**。
- **气泡引线的端点要落在序号牌圆圈边缘，不能落在圆心**。端点（`.rb-dot`）本身 7px、
  带光晕后视觉直径约 13px，落在圆心上就把序号数字糊掉（用户截图：长安站的「5」被盖住）。
  退回量 `t` 解 `|−u·t − off| = R`，其中：
  - `R` 是圆圈的屏幕半径，由 sprite 的屏幕尺寸换算 —— 两份 `numberTexture` 都是 128px
    画布但圆的半径不同：`effects.js` 是 `arc(46)+lineWidth 5` → 外缘 48.5 → ×**0.758**，
    `globe.js` 是 `arc(52)+lineWidth 7` → 外缘 55.5 → ×**0.867**；
  - `off` 是**圆心相对锚点的屏幕偏移**。锚点并不落在圆心上（3D 下它取「牌中心 + 0.31·comp」，
    约 10px 偏高），所以只回推一个 `R` 是不够的：端点会停在圆内偏上，仍然压着数字
    （实测 3D 扬州站端点距圆心只有 3px，而圆圈半径 25px）。
  引线长度也要同步缩短，否则它会穿进圆圈、在数字上留一条金线。
- **移动端（视口 < 548）行迹气泡改成上下两条带**，中间留 ≥ 120px 空白给地图与行迹。
  窄屏下宽屏那套「左右两栏」会退化成贴着右边缘的一整列 —— 实测 390×844 里 9 张卡全挤在
  x=194，从 y=153 一直糊到 y=688（用户截图）。分组按**锚点的屏幕纵坐标**对半分：靠上的进上带、
  靠下的进下带（与宽屏按横坐标分组同源，引线最短）；带内再按**锚点横坐标**分列，避免
  「左列的卡片指着屏幕最右边的点」。横向区间**不读 dockRect()** —— 抽屉展开时 dock 会退化成
  `left > right`（实测 389 / 350，availW 为负），而且 dock 缓存只在部分事件里失效
  （`setRoutePanelHidden(false, {quiet:true})` 那条路径）。这里跟 `measureInset()` 一致：
  窄屏下面板是盖在地图上的抽屉、按 0 计，左右各留 34px（抽屉开关 30 + 4 余量）。
  行距默认 8px，两带加起来挤不下才压到 2px；CLEAR_MIN = 120 是硬需求（不能让中间那条消失）。
  判据由 `tools/e2e-mobile.js` 的第 3b 节守着：顶带贴顶、底带贴底、中间留出 ≥ 120px 空白、
  卡片不压抽屉开关。
- **HUD 经纬度读数随缩放细化**：默认 2 位小数，拉近到约 3 倍 / 8 倍时升到 3 位 / 4 位
  （1° 纬度 ≈ 111km，故 2 位 ≈ 1.1km、4 位 ≈ 11m）。判据用「参考深度 / 当前深度」而不是
  绝对距离，窗口尺寸变化时不会漂；鼠标不动、只滚轮缩放时也会在渲染循环里重刷一次读数。
- **拾取**：先射线检测光柱柱体，再在命中的候选中取「屏幕距离最近」者，避免前排站点遮挡后排。
- **后期**：UnrealBloomPass + OutputPass（ACES 色调映射）。
- **性能**：所有贴图程序化生成（径向光晕、云海），无外部图片；地图数据抽稀至 1.7 万点。
- **显隐统一走 `.hidden` 工具类**：`css/style.css` 顶部定义了 `.hidden { display: none !important; }`，
  所有弹层（搜索下拉、练习卡、行迹面板、悬浮提示）只靠这一个类控制显隐，组件不再各写一条
  `.xxx.hidden` 规则。**注意 `!important` 不能省**——各组件自身都定义了 `display`，
  同特异度下后出现的规则会盖掉普通的 `.hidden`，导致 JS 加了类元素却依然可见。
  `tools/validate.mjs` 的第 10 项检查会静态校验这一点。
- **诗篇标签栏限高**：`.poem-tabs` 设了 `max-height: 56px; overflow-y: auto`。
  诗篇多的站点（长安 13 首、课内诵读 77 首）标签会排成好几行，不限高就会把正文挤出视野。
- **教材扩容批独立成文件**：`js/data/poems-textbook.js` 里每条诗带一个 `site` 字段，
  由 `js/data/poetry.js` 在聚合时按站点分桶并入。这样 233 篇教材篇目集中在一处、便于与
  `tools/textbook-list.mjs` 对照核对，而不必散落到各个 `sites-*.js` 里去找位置。
- **2D 模式不换相机**：版图是用 `ExtrudeGeometry` 挤出的水平顶面，从正上方俯视时顶面本身没有
  透视畸变、侧壁又被自身遮住 —— 视觉上与一张平面地图等价。所以 2D 只做三件事：
  正上方取景（`VIEW.flat`）、收起三维装饰（光柱 / 云海 / 星空 / 泛光）、锁定旋转。
  这样不必维护第二台相机、第二套控制器和两套取景逻辑。
- **2D 的落点标记是「小圆点」，不是放大的地面光圈**。光圈是「三维里一盏灯落在地上的光晕」，
  俯视成平面地图后它又大又糊（外径 35px），旁边再画一个圆点就成了重影。
  现在是 `dot`（直径 13px，朝代色填充）+ `rim`（深色描边外径 17px，浅色地形上也要看得见）两片几何，
  都在 `createBeacons` 里一次建好、按模式切 `visible`。直径由**屏幕像素反推**：
  默认取景时版图约 8 个世界单位宽、落在约 760px 可视区 → 约 0.0105 世界单位/px，故取 `DOT_R = 0.07`。
  2D 下点位不做呼吸动画 —— 平面地图上点位一闪一闪反而干扰读图。
- **2D 的地名标签改为左对齐排在圆点右侧**：`updateLabels()` 在 2D 下给屏幕坐标加 `SIDE_DX = 14`，
  并给元素加 `.side` 类把 `transform` 从「居中」改成「左对齐 + 垂直居中」，`::before` 补一小段渐隐引导线。
  原来的居中标签会直接压住刚落下的圆点。
- **2D 的行迹线路是一条「等高」折线**：逐点贴各自省份高度会被更高的台面遮住
  （四川 0.96 vs 江苏 0.16，俯视下表现为「线断了一截」）；抬到最高站点之上
  （`FLAT_ROUTE_CLEAR = 0.08`）则全程无遮挡 —— 而俯视投影里高度差不产生屏幕位移，不会失真。
  2D 下不抬弧线：弧线在俯视下不产生屏幕位移，只会让线偏离真实走向。
  序号牌就是落点标记：`FLAT_BADGE_LIFT = 0.12`（几乎贴地）+ `FLAT_BADGE_K = 0.72`（缩小），
  且必须 `depthTest: false` + `renderOrder 6`，否则会被相邻省份的台面吃掉。
- **2D 行迹里，序号牌要「顶掉」落点圆点**（`_applyDotVisibility`）。序号牌与圆点锚在
  **同一个坐标**上，而序号牌的圆底是半透明的（0.94）、圆点是纯色实心圆盘 ——
  圆点会从圆底里透上来，在数字正中糊出一块亮斑（实测长安那一站的「2」下半截被糊掉，
  用户报的就是「序号看不清」）。所以行迹覆盖的站点在非 3D 档不画圆点：
  序号牌本身就是那个站点的标记。判定写成 `this.mode !== '3d' && !this.routeStationIds.has(id)`
  两条闸门 —— 少第一条，3D 档会把本该看不见的圆点打开；少第二条，2D 下就还是重影。
  `routeStationIds` 是**这条行迹**的属性而不是视图的属性，所以换诗人（`buildRoute`）、
  退出行迹（`clearRoute` → `_syncRouteStations(null)`）、切视图（`setMode`）三处都要重算。
  `clearRoute` 里那句归还圆点曾经漏掉过（同一批编辑里静默失败），后果很隐蔽：
  光柱、序号牌、面板全部正常，只有地图上少了一片圆点 —— 是 `e2e-region` 第 9 节的
  「退出行迹 → 2D 下落点圆点全部回来」把它揪出来的。这也是为什么那条断言配了两条负向验证：
  一条查「没被行迹覆盖的站点圆点还在」（防「2D 下圆点一律不画」的恒真断言），
  一条查「退出后全部回来」（防「只借不还」）。
- **三种视图的行迹必须整条重建，不能共用几何**。版图是 Albers 投影 × 9.2 缩放（1 世界单位 ≈ 100km），
  地球是半径 1 的球（1 世界单位 ≈ 6371km）—— 版图行迹的弧线中点要抬 0.55~3.6 个世界单位，
  放到球上就是 **3.6 个地球半径高的巨型管子**，那正是「地球模式下路线又粗又飘」的成因。
  所以 `setViewMode()` 末尾统一调 `rebuildRoute()`：按新视图重画几何、重建气泡、重算聚焦集合。
- **视图三选一收成唯一入口**：`setViewMode('3d' | 'flat' | 'earth')`。
  原先 2D 与地球各有一个自己的 on/off，进入地球时会顺手退出 2D，但反过来
  「在地球模式下点 2D」不会退出地球 —— 两个模式同时成立：地球层与版图层都可见、
  极角限制与近裁剪面互相打架。现在先退旧的（`noView` + `quiet`，中间那次退出不取景）
  再进新的，最后 `syncViewButtons()` + `rebuildRoute()`。
  按钮高亮只在 `syncViewButtons()` 一处维护 —— 别处再点一遍就会漏掉「从地球切 2D 时把地球按钮摘掉」。
- **地球上的行迹走大圆航线**：站点间用 slerp 采样，抬起量与两地夹角成正比
  （`min(0.11, 0.012 + ang * 0.055)`，跨得越远弧越明显）且贴着地表飞；
  序号牌贴在站点正上方一点点（`dir × (surfaceRadius + 0.016)`，按**该点自己的**地表半径算 ——
  用固定半径会让高原上的序号陷进山里），并且也进拾取表（行迹模式下的序号就是站点标记）。
  行迹取景由**视场角反解**球面距离：`tan φ = R·sinθ/(d − R·cosθ)` ⇒ `d = R·cosθ + R·sinθ/tanφ`，
  θ 取行迹最大半张角 + 0.10，φ 取横竖视场里较小的那个，保证横竖两个方向都装得下。
- **地球序号牌要「小而不糊」**：屏幕尺寸 = `baseScale × fpx / 基准深度`，与缩放无关，
  1440×900 下取 `baseScale = 0.070` → 约 27px（地标是 13.9px）。
  贴图里的字号必须**顶到圆盘边上** —— 128px 的贴图缩到 27px 是 4.7 倍降采样，
  贴图里多留一分白边，屏幕上就少一分笔画：`radius 52` / 74px 字（两位数退到 62px，否则顶破圆盘）
  量下来数字约 11px；早先 `radius 48` / 62px 字只有约 8.6px，放大 10 倍看只剩一团糊影。
  圆底的不透明度也要够实（0.94）：序号牌正好压在**加色混合**的地标光晕上，
  留的每一分透明都会把光晕漏上来，数字被洗淡。
- **球面行迹聚焦时，地标要整体让位**（`globe.setRouteFocus`）。这是 2D 那条修法的球面版：
  地标是加色混合的白晕，比序号牌还大一圈，又被泛光放大 —— 而序号牌就落在站点正上方
  0.016 个地球半径处，正好在光晕心里。早先的做法是「只隐藏行迹外的地标、保留被聚焦的那几站」，
  结果那几站的序号依旧被自己的光晕糊住。现在聚焦时**所有**地标一律收起（含被聚焦的站点）：
  序号牌本身就是站点标记，而且它自己也在 `pickables` 里，点选不受影响。
  退出聚焦即全部恢复 —— `e2e-earth.js` 里那条断言因此从「只留行迹上的地标」
  改写成「地标 0 个可见 + 序号牌数 = 站数」，并补了一条「序号牌落在站点地标的位置上
  （最大偏差 < 0.05 个地球半径）」防它飘走。
- **两个自定义下拉共用一套组件**（`ui.bindDropdown`）：搜索框的「巡游范围」和行迹面板的
  「选择诗人」现在都是抽屉式下拉。三个坑：
  1. **浮层必须挂到 `<body>` 下**。祖先只要有 `transform`，`position: fixed` 的后代就会
     相对该祖先定位 —— 面板收起用的正是 `translateX()`，浮层会跟着一起飞出屏幕。
  2. **`offsetWidth` 要在 `display` 恢复之后量**。菜单默认带 `.hidden`（`display: none`），
     此时 `offsetWidth` 恒为 0，据此设的 `min-width` 会让浮层缩成 166px（按钮 314px）。
     所以顺序是「先摘 `.hidden`、再定位」。
  3. **浮层位置要现算，不能照搬按钮的 `rect`**。底部工具条（`.bottombar`）是横向滚动容器，
     390 宽下 `scrollWidth 1093 / clientWidth 356` —— 按钮可以停在视口外（实测 `btn.x = 617`
     而 `vw = 390`），照搬 `rect.left` 浮层就飘到屏幕外、文字也看不清。现在：
     按可用空间现算上下方向并夹在视口内，按钮整个在视口外时先 `scrollIntoView`。
     打开时还会 `closeDropdowns()` 保证同时只开一个，`scroll`(capture) / `resize` 时重新定位
     （按钮滚出视口则直接关闭）。
  这三条都是「量出来的」，`e2e-layout.mjs` 的 390 / 480 两个视口就是专门盯这类偏移的。
- **气泡停靠带要实测而不是写死**：`ui.dockRect()` 直接读 `#routePanel` / `#leftPanel` /
  `#toggleLeft` / `#rightPanel` / `#toggleRight` 的 `getBoundingClientRect`，
  取「还在屏幕内的最靠内的那条边」—— 行迹模式左侧是 276px 的 `#routePanel`、探索模式是 272px 的
  `#leftPanel`，两者位置相同但宽度不同；两栏都能收起到屏幕外；抽屉开关贴在面板外缘也要让开。
  结果缓存到 `this._dock`，因为 `getBoundingClientRect` 每帧调用会强制同步布局；
  面板开合、视口变化、视图切换、`measureBubbles()`、`syncPanelToggles()` 都要 `invalidateDock()`。
- **引线要从「朝向锚点的那条边」出发**。类名 `side-left` / `side-right` 说的是**卡片自己在哪一栏**
  （尾巴因而挂在朝内那条边上），不是出线方向 —— 把两者当成一件事，
  会出现「左栏卡片的尾巴挂到左边缘、朝屏幕外指」，实测九条引线有七条方向反了。
  另外锚点横向正好落在卡片自己的宽度范围内时（华东几个站点投影到右侧停靠带就会遇到），
  横向引线会横穿卡片本身；这时改用 `.side-top` / `.side-bottom` 从卡片上/下边出线，
  长度通常只有一两百像素。
- **抽屉开关必须放在面板外面**：面板收起靠 `transform: translateX()`，而 transform 会给后代
  建立新的包含块 —— 开关若留在面板内部会跟着平移出屏（左栏只剩 5px、右栏几乎完全出屏），
  用户就再也找不到展开按钮。现在开关是 `<body>` 下的 `position: fixed` 元素，位置由
  `syncPanelToggles()` 按面板实际宽度算出，因此各响应式断点都不用单独写媒体查询。
  `tools/validate.mjs` 第 12 项会静态拦截「开关又跑回面板里」。
- **省份 → 诗词的索引**：`PROVINCE_SITES` 在启动时按 `provinceAt(site.lon, site.lat)` 把 79 处诗境
  分桶到省级行政区。用与光柱落点完全相同的判定，保证「点那根光柱」和「点那个省」得到一致结果。
  点省份时先射线检测省域网格（`map.hoverTargets`），命中后再查这个桶。
- **拾取优先级**：点击是「先光柱、后省域」。光柱的拾取体是竖直圆柱，斜视角下投影成一条又高又窄的
  竖条，所以判断「某点离光柱多远」要看**水平**距离而不是直线距离。
- **同一件事的多个侧面必须一起复位**：地图光柱、左侧诗境列表、右栏地区介绍、底部区域诗词条
  这四个侧面同源于「当前可见的诗境集合」。各自更新就会打架 —— 点开四川省看到 4 处诗境，
  再切到李白行迹（地图只剩行迹那 9 站，四川省内只剩峨眉山），右栏却仍列着 4 处，
  用户照着清单去地图上找，根本找不到。现在统一挂在 `applyVisibility()` 末尾的
  `refreshRegionPanel()` 上：可见性一变，四个侧面一起重算（筛选、行迹聚焦、进出练习都走这条路）。
  右栏用 `#detailBody.dataset.region` 记住「当前展示的是哪个地区」，显示诗境详情时该标记被清除，
  所以改筛选不会把用户正在看的诗境详情替换成地区介绍。
  退出行迹 / 练习模式时，被收起的底部诗词条会跟着回来（`refreshRegionPanel({ showBar: true })`）。
- **浮层不会自动避让，必须显式让位**：所有浮层都是 `position: fixed`，浏览器只按 z-index 叠，
  不会替你腾位置。底部诗词条（z 44、居中 980 宽）曾压住右栏 180px 宽（「代表篇目」被切掉）、
  左栏 55px、行迹面板 8.5k px²；右下角显示经纬度的 HUD（z 30）更是 **100% 落在右栏（z 35）底下**，
  只透过玻璃背景显出一层灰影。修法是拿一个 body 类当「让位开关」：`body.rb-open` 时把
  左右两栏、行迹面板、HUD 的 `bottom` 一起抬高，`body.quiz-open` 时藏掉 HUD
  （练习卡居中在底部，会整个压住它）。诗词条与练习卡的高度由 JS 实测写进 `--rb-h` / `--qc-h`
  （空状态与有卡片时高度不同、题目与反馈区还会让卡片忽高忽低，写死会露馅；
  练习卡那条用 `ResizeObserver` 盯着，免得逐个渲染路径去补测量时漏掉一条）。
  让位的方向也要选对：**能竖向让就别横向挤**。练习卡一度被写成「挤在两侧栏之间」
  （`width: calc(100vw - 左栏 - 右栏 - 24px)`），390 宽时两栏各占 ~50vw，这个减法算出**负数** ——
  而 CSS 的 `width` 不接受负值，整条声明在计算值阶段失效、卡片回退成 shrink-to-fit，
  实测只剩 163px：文字竖排成一列、高度反涨到 468px。现在卡片只受视口约束
  （`min(560px, 100vw - 24px)`），侧栏改为整体上移。
  注意让位规则要覆盖**所有**同位置的浮层 —— 行迹面板是独立类 `.route-panel`、不在 `.panel` 里，
  漏掉它就成了「行迹模式下点省份，诗词条压住站点列表」。
  这类问题数据层和 DOM 结构都看不出异常，只能量 `getBoundingClientRect()` 交集，
  所以回归里有一条通用重叠检测（`tools/e2e-region.js` 的 `recNoOverlap`）。
- **一个回调不要承载两件事**：`onQuizMode(on)` 的语义是「地图全亮、等用户点省份作答」，
  只有看图识诗需要 —— 补全诗句和飞花令是拿 `onQuizMode(false)` 来开题的。
  早先这里顺手把 `body.quiz-open`（= 练习卡打开了）也挂在同一个参数上，于是后两种题型
  练习卡开着却没有 `quiz-open`：HUD 不隐藏（实测被压 17.6k px²）、侧栏不让位，
  退出逻辑还会把刚收起的诗词条又拉回来（卡片×诗词条重叠 95k px²，整条被盖住）。
  现在拆成 `onQuizMode` 与 `onQuizCard` 两个回调，各自对应一件事实。
  教训：**当某个回调的参数开始需要「有时候也代表另一件事」时，就是该拆的信号**；
  这种错误在宽屏上未必看得出来（卡片 560 宽、位置又巧），是窄屏巡检顺出来的。
- **窄屏形态不是「把宽度调小」，是换一种布局**：≤860px 时两栏从「并排的常驻工具」
  改为「互斥的覆盖式抽屉」（`body.narrow` 由 `ui.js` 维护，与 css 同一来源）。
  三件事必须一起做，少一件都不成立：
  1. **互斥**（`setPanelHidden` 里展开一边就收起另一边）——否则 390 宽下两个 340px 的
     抽屉同时铺开，总宽 680px，比修复前更糟；
  2. **取景不占位**（`measureInset` 在窄屏直接返回 0）——抽屉盖在地图上、不占版面，
     若照常按面板宽度留白，`frameView` 会把地图挤进「抽屉之外的那条缝」里；
  3. **遮罩**（`#drawerScrim`，z-index 34）——抽屉要盖住的是**地图**，不是整个界面，
     所以遮罩压住 `#stage` 却压在顶栏 / 底栏 / 诗词条 / 练习卡之下。
  另外**跨过断点时要成对处理**：进入窄屏两栏都收起，离开窄屏要把它们恢复展开 ——
  只做前一半的话，手机横竖屏一切换就留下一张空荡荡的地图加两个不起眼的小箭头。
- **新规则会把旧规则的某一条属性顺手吃掉**：让位规则写作 `body.rb-open .panel`（特异度 0-2-1），
  窄屏形态规则写作 `body.narrow .panel.left`（0-3-1）—— 后者更高，会把 `bottom` 一并盖掉，
  于是窄屏下抽屉不再给底部诗词条和练习卡让位，实测重叠 56.5k / 96.5k px²。
  修法是把窄屏下的让位**重写一遍**（`body.narrow.rb-open .panel`），而不是去调旧规则的顺序。
  教训：**加一条更高特异度的规则时，要连同它「顺带覆盖掉的其他属性」一起补上** ——
  宽屏上完全看不出异常，只有窄屏巡检量交集才暴露。
- **键盘可用性有三处最容易整片丢失**，且都不是「少写一个 aria 属性」这种小问题：
  1. **全局 `outline: none`**。原先 `button, input, select { outline: none }` 一句抹掉所有焦点环，
     鼠标用户毫无感觉，键盘用户则完全不知道焦点在哪 —— 按 Tab 屏幕毫无变化，等于界面不可用。
     改用 `:focus-visible`（只在非指针方式获得焦点时匹配，鼠标点击不会凭空多出一圈金框）。
  2. **收起的面板仍可聚焦**。收起只靠 `transform: translateX()` 平移出屏幕，元素还在文档流里、
     还在 Tab 顺序里，焦点会一路跑到屏幕外那些看不见的按钮上。补 `visibility: hidden`
     （配一个等于动画时长的 `transition-delay`，滑动过程不受影响）让整棵子树退出 Tab 顺序。
     **不能用 `display: none`** —— 那会连滑动动画一起丢掉。
  3. **模态弹窗不接管焦点**。打开时把焦点移入、`Tab` 困在弹窗内、关闭时归还给触发元素，
     三件缺一不可；否则焦点会掉回 `<body>`，下次 Tab 又从页面开头重走一遍，等于丢了位置。
  另外，`div` + `onclick` 的列表项（诗境 / 行迹 / 搜索结果）键盘**完全够不到**，
  统一用 `keyboardActivate()` 补 `tabindex` / `role` / `Enter`·`空格`。
  没有把它们改成 `<button>`：这些类挂着大量布局样式（flex 行、`margin-left: auto` 推右端、
  多行截断），换成 button 会连带吃到 UA 默认的背景色与对齐，回归面大得多。
  `空格` 必须 `stopPropagation` —— 全局快捷键把空格当「开始 / 暂停巡游」，
  而那个处理器只排除了 `INPUT` / `SELECT`，div 上的空格会一路冒泡上去。

### 地球模式

- **贴图 `flipY` 不关就是一颗上下颠倒的地球**。three.js 的 `Texture` 默认 `flipY = true`
  （上传时上下翻转），于是 `uv.y = 0` 取到的是画布**最后一行**；而球面 UV 是「v = 0 在北极」，
  画布第一行才是北极 —— 两者正好相反。症状极具迷惑性：内蒙的橄榄绿跑到南半球，
  屏幕上是一片深蓝，看起来像「相机对着大西洋」或「光照打反了」。
  定位靠三步排除：先量屏幕上几个点的 `N·L`（全部 0.95+，排除光照）→
  再读贴图像素（内蒙 `[141,159,74]` 橄榄绿、西藏 `[161,117,80]` 褐色，数据也对）→
  逐个隐藏叠加层（水壳 / 两条描边 / 地标），画面暴露出**一块形状像南半球陆地的深蓝**，
  才锁定是贴图方向。修法一行：`tex.flipY = false`。
- **地标尺寸补偿必须逐地标按「它自己的深度」算，基准机位要显式给出**。
  屏幕尺寸 ∝ 世界尺寸 / 深度，而「深度」是地标自己到相机在视线方向上的分量，
  不是「相机到球心」的距离 —— 两者差一个球半径，比值 `d/(d−R)` 在 d 从 5.34 到 1.67 时
  从 1.23 涨到 2.53，用球心距离做补偿等于没补偿（实测地标照样涨 2 倍）。
  更隐蔽的是**基准取错了时机**：`captureRefAt` 若拿「相机此刻的位置」当基准，
  而那一刻相机还停在版图视角（距球心 17.8），基准深度就偏大近 4 倍，
  79 个地标被一律压成 3px 小点 —— 而表现却像「补偿系数不对」，而不是「基准错了」。
  现在基准由调用方显式传入（进入地球模式时相机**将要落到**的那处机位），
  回归里也单列一条「基准已建立」，把排查范围一步缩到调用点上。
- **`update()` 里不能 `return` 跳过写 scale**。没有基准时若直接早退，
  `sprite.scale` 会冻在上一帧的值上 ——「基准缺失」于是表现为「尺寸纹丝不动」，
  和「补偿正常工作」一模一样，负向验证就是这么被骗过去的（清掉基准后量到的还是 13.9px）。
  现在没有基准就退回原始尺寸（`comp = 1`），语义明确。
- **放大到最近处会把地球整个裁没 —— 近裁剪面要按模式切**。
  球面沿视线方向距相机的距离约是 `d − R`。地图档 `near = 0.5` 在 `d < 1.53` 时
  就把整个可见球面推进了近裁剪面之内：实测 `d = 1.35` 与 `1.10` 两档屏幕上只剩星空。
  地球档改 `near = 0.2`，退出时还原。也不能取更小：水面壳相对球面只抬升 `5e-4`，
  `near = 0.02` 时 `z = 14` 处的深度分辨力约 `5.9e-4`，两者同量级，海陆交界会起斑。
- **地球上的「可见跨度」由视场角决定，不是地平线**。视线边缘 φ = fov/2 对应的球心角 θ 满足
  `tan φ = R·sinθ / (d − R·cosθ)`，解出来：`d=5.34 → 164°`、`d=3.0 → 72°`、
  `d=1.4 → 12.6°`、`d=1.08 → 2.4°`。所以 `d` 从 1.4 走到 1.08 这「一小步」跨度缩了 5 倍。
  而高程数据是 1° 网格 —— `d=1.08` 时整屏只有 2.4 个数据格，双线性插值出来必然是一片平滑色块
  （实测阿尔卑斯上空：贴图在该处 9.5° 跨度内对比度 165，渲染出来只有 24，肉眼就是一片发白）。
  **最近距离因此由数据分辨率定，而不是由「能不能再靠近」定**：取 `EARTH_MIN = 1.4`。
  想再往里看要换更细的高程数据，不是把 `minDistance` 调小。
  回归里用射线量出真实跨度（二分找「最靠上还打得中」的那条射线），卡住 8°~25°。
- **主光的偏转要绕屏幕横轴，且不能随缩放收敛**。绕 Y 轴偏 off 时，光与视线的实际夹角是
  `off·cos(相机纬度)`：赤道附近 26°，转到极区只剩 4°，退化成无影灯。绕「视线 × 上方向」偏转，
  则处处都是同一个夹角。另外曾按「拉近后固定偏 31.6° 会让中国北方变黑」把偏移写成随缩放收敛，
  但那个「变黑」其实另有原因（就是上面的 `flipY`），诊断错了 ——
  收敛的后果是缩到最近处时夹角只剩 8.6°，光几乎正对镜头，地形起伏对法线的扰动退化成
  二阶效应（正射光下 `N·L ≈ 1 − α²/2`），整屏变成一片发白的平光，对比度量出来是 1。
  斜射光下同一扰动是一阶的（`≈ α·sinθ`），所以固定偏 30° 才对。
- **球面可见性要自己判**：表面点 P 对相机 C 可见 ⇔ `P·C > |P|²`。
  three.js 的射线检测**不看 `visible`、也不做遮挡判断**，必须显式剔除背面地标，
  否则「点空白处却选中了球后面看不见的诗境」。
- **近半球判定之外的第二个坑**：`pointermove` / `pointerup` 里也要显式分流 ——
  地球模式下地图那一整套虽然 `visible = false`，射线照样会打中它。
- **`Globe` 少初始化一个字段，整条航线会静默消失**。`markerComp` 是行迹管线用的全局补偿系数，
  但它原先只在 `effects.js` 里有定义，`Globe` 里从未初始化 —— 于是
  `0.0042 * this.markerComp` 算出 `NaN`，`TubeGeometry` 的顶点全变 `NaN`，
  球面上**一根线都画不出来**；而 `state.earth` / `routeGroup` / 序号牌 / 拾取表全都正常，
  光看「routeGroup 存在」根本发现不了，只有点进几何里数顶点才现形。
  现在 `Globe.markerScale(camera)` 给出与 `effects.markerScale` 同一条规则
  （相机到球心距离 ÷ 基准距离），并在构造时初始化为 1。
  回归里补了一条「球面航线几何没有 NaN 顶点」+ 对应的负向验证 —— 这类「状态全对、就是没画出来」
  的缺陷，只能直接读渲染产物（几何顶点 / 像素）才拦得住。
- **透明精灵的先后不能交给 z 排序，必须显式写 `renderOrder`**。
  地标、飞线光点、序号牌三者位置几乎重合，透明队列按「投影 z」排序，
  而序号牌只比地标往外挪了 0.016 —— 站点偏离画面中心时，这点**径向**偏移在视线方向上
  可能反而更远，于是地标（加色混合、光晕比牌子还大一圈）被排到后面画，
  整块序号牌被洗成一片白。实测长安那一站就是这样，肉眼看就是「序号根本没显示」，
  而 `routeBadges.length` / `sprite.visible` / `material.map` 全部正常。
  现在给 `renderOrder` 定死层级：深色底衬 1 → 航线 2 → 序号牌 4；
  远处被地球挡住的序号牌仍会被正常遮住 —— 遮挡靠深度测试，与排序无关。
- **发光航线下面要垫一层深色底衬**。全球底图在陆地上是明亮的橄榄绿 / 卡其色，
  加色混合的米金色压上去直接洗成一片白，航线在中国大陆上空几乎看不见。
  加一条 `R_TUBE × 1.8` 的深色描边（`0x0a1524`、opacity 0.55）之后亮地形上也读得出线形，
  深色海洋上则靠上层发光取胜 —— 与地图上「江河」的处理是同一个思路。
  底衬的几何要跟着补偿系数**一起重建**，否则拉近时两层粗细会脱节。
- **视图层显隐不能只跟「user toggle」走**。`applyEarthMode(true)` 把
  `rivers.visible = false` 藏好了，但 `setViewMode → rebuildRoute → applyVisibility()`
  又把它无条件拉回 `state.layers.rivers = true`，于是黄河 / 长江 / 京杭大运河
  按版图坐标系（1 世界单位 ≈ 100km）画的管子直接横在半径 1 的球上，尺寸离谱。
  修法：所有「A 视图是装饰、B 视图不该出现」的层，visibility 公式都是
  `user_toggle && view_compatible`（河流：`!state.earth`，云海同理）。
  这条要在**所有**写 visibility 的入口都加 view-mode 闸门，不能只加在视图切换那一处。
- **「ripple 是直接 add 到 scene 的」是隐藏陷阱**。涟漪在 `effects.ripple(siteId)`
  里 `this.scene.add(mesh)`，**不在** `beaconGroup` 下 —— 所以
  `applyEarthMode` 设的 `beaconGroup.visible = false` 拦不住它，
  ripple 按地图档坐标创建（RingGeometry 0.2~0.3 世界单位 ≈ 一个省份直径），
  落到地球档上位置甩到地球外 + 6 倍放大 → 用户看到的「位置不对的大光环」。
  修法：`effects.setMode` 扩成 `'3d' | 'flat' | 'earth'`，earth 模式清空 ripple 数组；
  `setSelected` 加 `this.mode !== 'earth'` 闸门拦截新 ripple 创建。
  这一类**「父 group 隐藏拦不住」**的陷阱不止 ripple —— 任何**绕开父 group 直接 add
  到 scene** 的临时装饰都得在视图切换时主动清，否则会跨模式乱串。
- **地球档「点空白处」也得能命中省份**。原来 `pointerup` 地球档直接 return，
  但用户从地图档的习惯里带着「点哪都行」的预期。修法：地球档下没点中地标时
  走 `globeLonLatAt() → provinceAt() → map.hoverTargets 找 mesh → focusProvince`。
  `map.hoverTargets` 在地球档不可见但 userData 仍可用，省钱 cosmetica。
- **省份「选中」≠「hover」**。这是两层独立状态：
  - `userData.hovered` 是鼠标正指着（瞬时），`updateProvinces` 拿来抬升 + 变色；
  - `userData.selected` 是点过的（要留住），哪怕鼠标已经移到诗词卡片上
    那一块也得保持抬起 + 边界线橙金 + 不透明度 0.95，否则「我点的是哪一块」会丢。
  两个状态在 `updateProvinces` 里**合并判断**：`const active = u.hovered || u.selected`，
  抬升 / 顶面色 / 边界线都跟着 `active` 走。
  早期 focusProvince 写成 `m.userData.hovered = m.adcode === u.adcode`（漏了 userData），
  Mesh 上没有 adcode 字段，恒为 undefined —— 这一句把**所有**省份的高亮都置成 false，
  点了省份高亮反而当场熄灭；并且即使没这个 bug，hovered 也是瞬时的（鼠标一走就灭），
  同样看不出「点中」。修法：focusProvince 写 `m.userData.selected = m.userData.adcode === u.adcode`，
  收起诗词条时 `ui.hideRegionBar` → `ctx.onHideRegion` 把 selected 清掉。
- **省份边界线必须挂在各省 mesh 下跟随 lift**。早先挂在 root 直属的 `borderGroup` 里，
  省份 hover 抬升 0.22 时线留在原地，抬起来的那块与地面之间裂出一道缝；
  改成 `mesh.add(lineMesh)` 才跟着走。同时各省份 `borderMat.clone()` 拿到独立材质实例，
  否则 lerp 会串台：点亮一个省，全省边界线一起变橙 —— 等于没有选中效果。
  选中态颜色用饱和橙金 `#ffb84a`（与未 hover 的 `#e8c07a` 拉开对比度），
  早期试过 `#ffd07a` 太接近，淡金 lerp 到淡金肉眼根本分不出来。

新增的每条防线都做了负向测试，确认它**会真的响**，而不是恒真的摆设：

| 防线 | 怎么改坏 | 期望报出 |
| --- | --- | --- |
| 高程网格字节数 | 截断 base64 | 字节数与 Int16 不符 |
| 高程范围声明 | 改 `min` 不改数据 | 声明与实际不符 |
| 陆地轮廓合法性 | 坐标改成 −999.57 | 越出经纬度范围 |
| 海陆掩膜 | 删掉含北京的环 | 海陆掩膜判错 |
| 全局极值 | 高程值减半并同步改 range | 深海地形被削平 |

| 领土要素 | 去掉台湾省 | 中国版图数据缺少「台湾省」 |
| 疆域范围 | 版图坐标改成 217.35 | 越出疆域范围 |
| 地标补偿基准 | 清掉 `markerRef` 与 `refDepth` | 尺寸明显变化（比值 6.39） |
| 可见性判据 | 把 `root.visible` 设 false | 判据读的是渲染结果而非状态字段 |
| 近裁剪面像素判据 | 把 `camera.near` 推到 6 | 中心区亮像素 100% → 0% |
| 地球地名标注闸门 | 把 `EARTH_LABEL_DIST` 调成 1 | 默认太空视角可见 ≠ 0 |
| 地球右键绑定 | 把 `mouseButtons.RIGHT` 设回 PAN | 拖动后方位角变化 < 6° |
| 地球右键菜单拦截 | 移除 `contextmenu` 监听 | `contextmenu.defaultPrevented` = false |

| 行迹聚焦（球面） | 清掉 `routeFocus` | 79 个地标全部重新可见，不再让位给序号牌 |
| 2D 落点圆点让位 | 把 `routeStationIds` 清空 | 被覆盖的站点又画回圆点，序号牌重新被糊（见 `e2e-region` 第 9 节的负向两条） |

## 数据说明

- 地图边界来源于国家测绘标准审图号地图的公开矢量化版本（DataV.GeoAtlas / 高德开放平台坐标系），
  经几何抽稀后使用，**仅供教学可视化，不作为权属界线依据**。
- 诗词正文、注释、译文与赏析为教学用途整理，如用于正式出版请另行校勘。
- 江河走向为示意性简化折线，用于课堂讲解，非精确水系数据。
- **地球模式的全球底图**（`js/data/world.js`）：
  - 高程：NOAA / NCEI **ETOPO1** Global Relief Model（Amante & Eakins, 2009），
    1 弧分原始数据按 1° 步长抽样，得 361(经) × 181(纬) 网格，单位米，
    以 Int16 小端序存 base64（174KB 字符）。
  - 陆地轮廓：**Natural Earth 1:110m physical "land"**（公有领域），量化到 0.01°，
    127 个外环 + 1 个内环，共 5001 点。**只描述海陆分界，不含国界。**
  - 全球底图**不画任何政治边界**；地球上的中国版图由中国标准地图数据（`js/data/geo.js`）叠加，
    含台湾省、香港特别行政区、澳门特别行政区及南海诸岛（九段线）。
- **全球底图数据不含任何政治边界**这条约束由静态校验守着：
  `world.js` 的导出清单必须恰好是 `LAND_HOLE, LAND_OUTER, WORLD_ELEV` 三项，
  多出任何一层都会让校验失败。

### 数据校验

改动诗词数据后请运行校验脚本，确保不会破坏检索与出题：

```bash
cd poetry-3d-map
node tools/validate.mjs     # 全绿输出「✅ 全部校验通过」
node tools/coverage.mjs     # 教材覆盖率应为 100%
```

校验覆盖 12 类规则：

1. 字段完整性 —— 含**站点经纬度不得重合**（重合的两个站点在三维场景里会叠成同一根光柱，看起来少了一处诗境），
   以及**坐标精度与间距**三条守卫（见下方说明）
2. 诗篇逐条（联数与译文数一致、**意象字必须是单字且真实出现在正文中**、朝代可映射）
3. 标点规范（句末标点可被右引号包住；近体诗另要求上句以逗号收、中间各联下句以句号收）
4. **朝代筛选覆盖（检测死选项）**
5. 朝代分布
6. 行迹站点引用
7. 自动出题（选项无重复且含答案、飞花令例句充足）
8. 检索
9. 统计一致性
10. **`index.html` 中每个带 `hidden` 类的元素，都必须有 CSS 规则真正把它隐藏**
11. **教材扩容批归属** —— `poems-textbook.js` 里每条 `site` 都必须指向真实站点，且该诗确实被聚合进了那个站点
12. **抽屉开关位置** —— `.panel-toggle` 不得出现在 `.panel` 内部
13. **全球底图数据** —— 高程网格字节数与 Int16 一致、声明 range 与实际一致、10 个采样点高程落在期望区间、
    全局极值合理（最低 < −8000、最高 > 5500）、陆地轮廓逐环合法、12 个采样点海陆判定正确、
    `world.js` 只导出高程与海陆轮廓、中国版图含台湾省 / 港澳 / 南海诸岛且顶点不越出疆域

> 第 10 项踩过的坑：JS 反复给搜索下拉加 `hidden` 类、类也确实加上了，但 CSS 里漏写
> `.search-results.hidden`，于是下拉框永远关不掉。**教训是验证界面状态必须断言渲染结果
> （`getComputedStyle(el).display === 'none'`），而不是断言类名（`classList.contains('hidden')`）
> ——类名是意图，渲染结果才是事实。**
>
> 第 11 项踩过的坑：`site` 写错时诗篇会被静默丢弃（分桶后没人来取），从数据层看不出任何异常。
>
> 第 12 项踩过的坑：开关原本是 `.panel` 的子元素，面板靠 `transform: translateX()` 收起时
> 把它一起带出了屏幕，用户「收起后找不到展开按钮」。CSS 与数据层都看不出异常，
> 只有到浏览器里点一次才暴露。
>
> 意象字若写成了正文里不存在的字（如把「芙蓉」记作「花」、把「蜡炬」记作「烛」），
> 详情页的意象字标签就会指向空结果；校验脚本会直接拦截这类错误。
> 近体诗（绝句 / 律诗）要求两句一联；词、散曲、古体诗、乐府、楚辞、歌行的一个「组」
> 是一个句读单元，内部可含多个逗号分句（如《念奴娇》「大江东去，浪淘尽，千古风流人物。」），
> 但组内最多放两个字符串。

**关于站点坐标精度**：地图现在可以拉近约 14 倍（默认视域约 262km 宽 → 最近约 19km），
站点间距第一次变得「看得见」，所以第 1 类里补了三条守卫：

- **坐标必须落在 0.01° 网格上**（≈1.1km）。这是这批数据的既定精度。
  注意不能按字面小数位判断 —— `119.6` 就是 `119.60`，尾零被省略而已，
  按字面判断会误报 27 处；也不能要求 3~4 位：这些诗境多为江、山、关这类
  **面状**地点而非点，再补位数是假精度。已抽查 20 处地标（黄鹤楼 114.3020/30.5449、
  华清宫 109.2167/34.36、玉门关 93.86/40.35、滕王阁 115.877/28.682……），
  2 位小数与真实坐标均在 1km 内吻合；在最大放大倍率下 0.01° 也只有约 3px，
  肉眼不可分辨。
- **必须落在国境经纬度范围内**（lon 73~136 / lat 3~54）。经纬度写反（lon/lat 互换）
  在数据层完全看不出异常，到三维场景里却是「光柱跑到国外」。
- **两站间距 ≥ 1.5km**。标记的屏幕尺寸是恒定的（见下），最近处光圈约 45px（≈0.6km），
  再近就会互相盖住。当前最近的一对是金陵 ↔ 秦淮（5.8km），余量充足。

### 界面回归（浏览器端）

静态校验只能保证数据自洽，界面行为要在真浏览器里跑。`tools/` 下有六个注入脚本，
外加六个 runner 各回答一个问题：

```bash
cd poetry-3d-map
python3 serve.py &                  # 先起静态服务器
node tools/e2e-all.mjs              # 功能回归：一个视口（1440×900）跑三套注入脚本（218 项）
node tools/e2e-layout.mjs           # 布局巡检：八个视口量重叠 / 溢出 / 元素宽度
node tools/e2e-a11y.mjs             # 键盘回归：发真实按键量 Tab 顺序与焦点（35 项）
node tools/e2e-bubbles.mjs          # 气泡层回归：16 条行迹逐条量气泡数 / 不重叠 / 不出界 / 停靠左右 / 出线方向 / 有内容
node tools/e2e-zoom.mjs             # 缩放回归：滚轮放大时标记屏幕尺寸是否恒定 + HUD 精度是否随缩放提升（24 项）
node tools/e2e-mobile.mjs           # 窄屏回归：只在 390×844 跑，量横滚底栏里的下拉浮层 / 诗人下拉 / 选完诗人自动收起面板 / 抽屉开关 / 行迹气泡上下分带（52 项）
node tools/e2e-earth.mjs            # 地球模式回归：进出恢复 / 球面起伏 / 地标 / 领土要素 / 相机 / 近裁剪面像素判据 / 球面行迹 / 地球地名标注 / 右键拖动 / 点选 ripple 闸门 / 地球档点省份识别（126 项）
```

**注入脚本怎么跑：别把整个脚本塞进一次 `eval`。**
`agent-browser eval` 对**单次调用**有等待上限，超了会报

```
✗ Failed to read: Resource temporarily unavailable (os error 35)
  (after 5 retries - daemon may be busy or unresponsive)
```

这条文案完全指不到「脚本太长」上 —— 它长得像 daemon 挂了 / 端口不通 / 环境坏了。
实测（macOS，agent-browser 0.25.3）：`eval` 一个 `sleep 20s` 的异步表达式 21s 正常返回，
`sleep 90s` 的则 2m35s 后失败。同一份脚本拆短跑却全绿。

所以所有 runner 统一走 `tools/ab-run.mjs` 的 `runScript()`：**派发 + 轮询 + 取结果**三步，
每一步的 eval 都是毫秒级 —— 脚本多长都不怕。附带好处是脚本内抛异常时能拿回**完整堆栈**
（以前 CLI 会把堆栈吞掉，只留一句 `Command failed: agent-browser eval …`，只能靠二分注释定位）。

历史上这个坑被误判过两次，两次都写下了错误的结论，这里一并订正：
`e2e-earth.mjs` 曾把第 10 / 12 节拆成独立文件，注释里写的是「daemon 需要喘息窗口」——
真正的变量是**单次 eval 的时长**，拆文件只是碰巧把每次调用压短了；
`e2e-region.js` 断言越加越多、累计 sleep 从约 40s 涨到约 47s 越线后，
则被当成「脚本里有 bug」查了半天。现在两处注释都已改写成事实。

**为什么不是一套**：它们回答的是七个不同的问题 ——
`e2e-all.mjs` 问「功能对不对」，`e2e-layout.mjs` 问「摆得下吗」，
`e2e-a11y.mjs` 问「键盘能不能用」，`e2e-bubbles.mjs` 问「**站点多 → 塞得下吗**」，
`e2e-zoom.mjs` 问「**放大之后，标记有没有跟着一起变大**」，
`e2e-earth.mjs` 问「**换了一整层几何之后，进出还干净吗、拉近还看得见吗**」，
`e2e-mobile.mjs` 问「**手机上那些覆盖式抽屉和浮层好不好用**」。
混在一起跑会得到一个误导性的绿灯：功能全对、布局全错，而报告只写「全部通过」。
布局类缺陷只在特定宽度才出现，1440 下量什么都是对的；
键盘类缺陷则只有**发真键**才测得出来（见下）；
气泡类缺陷则只有**每条行迹都跑一遍**才测得出来 ——「李白 9 站能撑开」不保证「杜牧 6 站也能」；
缩放类缺陷则只有在**拉到最近**时才暴露 —— 默认视角下量什么都是对的（补偿系数恰好为 1）；
地球类缺陷则**所有状态字段都是对的**：`state.earth === true`、`root.visible === true`、
相机距离也合法，只有画出来是黑的（近裁剪面把球整个裁掉那一段就是这么发现的）；
窄屏类缺陷则**在宽屏上根本不存在**：底栏不是滚动容器、面板不是覆盖式抽屉、
抽屉开关也不会被挤到屏幕边缘外 —— 只有在 390 宽下才复现（`e2e-layout.mjs` 只管几何，
「浮层飘出视口」是几何能测的，「浮层挡住了按钮」「选完诗人后地图只剩 50px」是几何测不出的）。

`e2e-all.mjs` 会在**每套脚本跑之前重新导航页面**，保证脚本之间零状态污染。这不是洁癖，
是踩出来的：三套脚本共用同一个浏览器会话，而 `e2e-scene.js` 第 12 段会把 `#viewGroup` 里
所有视角按钮都点一遍（含后来新增的「2D 平面」与「地球」），而这两个是**互斥**开关 ——
点完「地球」页面就停在太空视角；紧接着跑的 `e2e-region.js` 里「切 2D」系列断言就会因为
`setViewMode` 开头的「已经是目标模式就早退」而**全部假失败**，看起来像功能坏了，其实只是状态脏了。

修复分两层：`e2e-scene.js` 跑完主动 `setViewMode('3d')` 并关掉自动旋转（**治本** ——
实测只做这一步，连跑就已全绿），以及 `e2e-all.mjs` 每套前 reload（**结构性保险** ——
以后新增脚本忘了复位也兜得住）。

手动单跑某一套时，**不要**直接 `agent-browser eval "$(cat …)"` —— 长脚本会撞上面那条超时。
用 runner 里的同一个执行器：

```bash
node -e "import('./tools/ab-run.mjs').then(async ({makeAb, runScript}) => {
  const fs = await import('node:fs');
  const ab = makeAb();
  const { R, ms } = runScript(ab, fs.readFileSync('tools/e2e-region.js','utf8'), { label: 'e2e-region.js' });
  console.log(R.filter(r => !r.pass).map(r => '✗ ' + r.name + '  ' + r.extra).join('\n') || '全部通过');
  console.log(R.filter(r=>r.pass).length + ' / ' + R.length + '  ' + (ms/1000).toFixed(1) + 's');
})"
```

（短表达式仍然可以直接 `agent-browser eval "document.title"`。）

### 键盘回归（必须发真实按键）

`e2e-a11y.mjs` 是一个 **Node runner**，不是注入脚本 —— 因为「焦点可见」与「Tab 顺序」
这两件事**只有真实按键才测得出来**：

- `:focus-visible` 匹配与否，取决于浏览器认定的「最近一次输入方式」。在页面里 `el.focus()`
  属于程序化聚焦，浏览器不认；用它去断言 `:focus-visible` 会得到假阴性 ——
  明明鼠标点不出焦点环、键盘点得出，脚本却两边都测成一样。
- Tab 顺序是浏览器的默认行为。用 `dispatchEvent` 造一个 `keydown` 出去，浏览器不会替你移动焦点，
  测出来的永远是「焦点没动」。

所以它用 `agent-browser press Tab` 发真键，每按一次回页面里问一句「现在焦点在谁身上」，
断言的是 `document.activeElement`、它的 `outlineStyle`、以及它是不是真在某个可见容器里。共 22 项：

| 分组 | 覆盖 |
| --- | --- |
| 宽屏 Tab 顺序 | 首个 Tab 落在搜索框；顶栏之后进入侧栏内容（而非跳过侧栏直奔边缘开关）；每一站都有可见焦点环 |
| 窄屏 Tab 顺序 | 收起的两栏不出现在 Tab 顺序里；抽屉开关本身仍可 Tab 到；**负向对照**：打开左栏后其内容必须重新可聚焦（否则「收起来够不到」也能靠「一律隐藏」蒙混过关）；遮罩出现与点击收起 |
| 弹窗焦点 | 焦点移入弹窗；连按 8 次 Tab 不逃出；Esc 关闭后焦点归还触发元素 |
| 列表项键盘激活 | 诗境列表项 `tabindex` / `role`；`Enter` 选中的正是该项；列表项上的空格**不会**顺手触发巡游；搜索框 `↓` 把焦点交给结果项 |

> 两个踩过的坑：
>
> 1. **`blur()` 不能把 Tab 起点复位。** blur 之后 `activeElement` 确实变回 `<body>`，
>    但浏览器记着「顺序焦点导航的起点」，下一次 Tab 仍从刚才那个元素往后走。
>    于是「点击开关 → blur → Tab」会直接从开关的下一个元素开始，跳过它前面的整个左栏，
>    看起来像「左栏内容不可聚焦」，其实只是没从头走。可靠的办法是一路 Tab 回到已知的第一站。
> 2. **`agent-browser eval` 的返回值是「JSON 文本」**。若页面里返回的已经是一个 JSON 字符串，
>    拿到的就是带引号的 JSON 字符串，`JSON.parse` 一次得到的是**字符串**而非对象 ——
>    spread 出来全是下标键，所有字段读出来都是 `undefined`，表现为「脚本在跑、断言全错」。
>    要再解一层。

### 布局巡检（多视口）

`e2e-layout.mjs` 在**一组**视口里各跑一遍 `e2e-layout.js`，量的是几何而非行为：

| 检查 | 口径 |
| --- | --- |
| 浮层互相遮挡 | 两两求 `getBoundingClientRect()` 交集，必须为 0 |
| 让位过度 | 让位后侧栏高度 < 190px、诗词条宽 < 240px 也算失败 |
| 练习卡宽度 | **不变量**：必须正好等于 `min(560px, 100vw - 24px)` |
| 横向溢出 | 只看自己不能滚的容器（`.bottombar` 是设计上就横向滚动的，跳过） |
| 右溢视口 | 元素右边缘不得越过视口 |
| **窄屏两栏互斥** | 窄屏下左右两栏不得同时可见（同时可见即「地图被夹成一条缝」的病根） |
| **窄屏抽屉留缝** | 抽屉宽度 ≤ `100vw - 48px`，总要在另一侧留出 ≥32px 的地图缝隙 |

视口刻意取在每个响应式断点的**两侧**（断点 1280 / 1080 / 860 / 640）：
`390 / 480 / 640 / 861 / 1024 / 1081 / 1281 / 1440`。
「某个宽度忘了覆盖」这类错误正好藏在断点右边的缝隙里 ——
`.panel.right` 在 ≤860 用了 `50vw` 约束而 `.panel.left` 漏了，390 宽下两栏同时展开
水平重叠 57px；而左栏在窄屏默认收起，只有专门造出「两栏全开」这个状态才复现得出来。
所以巡检里除了默认状态，还要**主动构造组合状态**（两栏全开 / 三种练习各一遍 / 行迹 + 点省份）。
窄屏下「两栏全开」这一步的含义变了 —— 它验的不再是「摆不摆得下」，而是**互斥到底有没有生效**
（两个开关都点过之后，必须恰好只有一栏处于展开状态）。

> **写这类脚本时踩过的三个坑，值得记下来：**
>
> 1. **别用「省域中心」当点击点。** 三维浮雕地图里各省台面高度不同，射线可能先打中更近 / 更高的邻省
>    （甘肃是狭长弧形，其中部会被海拔更高的青海台面挡住）。脚本必须用与主程序相同的射线逻辑
>    复核「这个屏幕点实际落在哪个省」，并在省内多取几个候选点。
> 2. **判断「离光柱多远」要只看水平距离。** 光柱是竖直圆柱，斜视角下投影成一条又高又窄的竖条；
>    用直线距离会挑到「直线 56px、水平仅 4px」的点，点击被光柱的拾取圆柱吃掉，测不到省份分支。
>    最稳妥的做法是直接调 `window.__app.pickBeacon({clientX, clientY})` 问主程序会不会被截走。
> 3. **脚本之间必须隔离，每套前 reload。** 见上文 —— 假失败的典型长相就是「单独跑全绿、连跑就挂」。
>    遇到这种症状先怀疑状态污染，别急着改产品代码。

### 气泡层回归（16 条行迹逐条跑）

`e2e-bubbles.mjs` 对 16 条行迹逐条选中，各量六件事：

| 检查 | 口径 |
| --- | --- |
| 数=站 | 气泡数必须等于该行迹的站数（差一个就是 `buildRouteBubbles` 漏挂 / 多挂） |
| 不重叠 | 两两求 `getBoundingClientRect()` 交集，必须为 0 |
| 不出界 | 卡片四边都在视口内（出界 = 引线指不到锚点） |
| **停靠左右** | 卡片必须落在 `ui.dockRect()` 实测的两条空白带里 —— 光看「不出界」是不够的，卡片全堆在画面正中同样不出界 |
| **有方向** | 每张卡片都带且只带一个方向类（`side-left/right/top/bottom`），决定引线从哪条边出发 |
| 有内容 | 每张卡片都装了诗作或显式「未见存世诗作」（留空会让用户以为是 bug） |

「停靠左右」这条是后加的：原先只验「不出界」，而卡片全堆在画面正中同样不出界 ——
用户要的是「诗词卡片放在地图的左右两侧空白区域」，所以要拿 `dockRect()` 实测的空白带当判据。

`e2e-region.js` 里另外三条更细的不变量（对应「引线要指得准」）：
出线那条边必须**朝向锚点**、锚点**不能被自己的卡片盖住**、引线长度 ≤ 620px（不能横穿整张地图）。

> 气泡类缺陷只有**每条行迹都跑一遍**才测得出来 ——「李白 9 站能撑开」不保证「杜牧 6 站也能」；
> 而且量之前必须**轮询到相机停稳**（取景飞行 1.7s，固定 `sleep` 会在途中测量，
> 锚点还在动，布点算法就会算出一堆假重叠，实测见过「5 对」「2 对」各一次，重跑又全绿）。
